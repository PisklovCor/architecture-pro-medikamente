# Аудит мер по обеспечению безопасности данных

## Введение

В данном документе проводится аудит текущего состояния безопасности данных в компании "Медикаменте" и сопоставление с требованиями российского законодательства (152-ФЗ "О персональных данных") и лучшими практиками в области информационной безопасности.

## Требования законодательства РФ

### 152-ФЗ "О персональных данных"

Основные требования:
1. **Определение целей обработки** - должны быть четко определены цели сбора и обработки персональных данных
2. **Согласие субъекта** - необходимо получение согласия на обработку персональных данных
3. **Меры защиты** - применение технических и организационных мер защиты
4. **Ограничение доступа** - доступ к персональным данным должен быть ограничен
5. **Контроль и аудит** - ведение учета действий с персональными данными
6. **Уведомление Роскомнадзора** - уведомление о начале обработки персональных данных

### Требования к медицинским данным

Медицинские данные относятся к категории биометрических и особо чувствительных данных, что требует:
- Повышенных мер защиты
- Строгого контроля доступа
- Обязательного шифрования
- Детального аудита всех операций

## Сопоставление текущего состояния с требованиями

### 1. Хранение персональных данных

| Требование | Текущее состояние | Соответствие |
|------------|-------------------|--------------|
| Шифрование при хранении | Данные хранятся в открытом виде в Excel и сканах | ❌ Не соответствует |

| Версионирование | Нет контроля версий файлов | ❌ Не соответствует |

### 2. Передача персональных данных

| Требование | Текущее состояние | Соответствие |
|------------|-------------------|--------------|
| Шифрование при передаче | Данные передаются по незащищённому TCP/IP | ❌ Не соответствует |
| Контроль передач | Нет логирования передач данных | ❌ Не соответствует |
| Безопасные протоколы | Использование OLE и незащищённых протоколов | ❌ Не соответствует |

### 3. Доступ к персональным данным

| Требование | Текущее состояние | Соответствие |
|------------|-------------------|--------------|
| Аутентификация | Только доменная аутентификация | ⚠️ Частично соответствует |
| Авторизация | Нет разграничения прав доступа | ❌ Не соответствует |
| Аудит доступа | Нет логирования доступа к данным | ❌ Не соответствует |
| Многофакторная аутентификация | Отсутствует | ❌ Не соответствует |

### 4. Обработка персональных данных

| Требование | Текущее состояние | Соответствие |
|------------|-------------------|--------------|
| Минимизация данных | Собираются все возможные данные | ❌ Не соответствует |
| Целевое использование | Нет контроля использования данных | ❌ Не соответствует |
| Сроки хранения | Нет политики удаления данных | ❌ Не соответствует |
| Права субъектов | Нет механизма реализации прав субъектов | ❌ Не соответствует |

| Требование | Текущее состояние | Соответствие |

| Контроль доступа | Нет ограничений на доступ к медицинским картам | ❌ Не соответствует |
| Аудит операций | Нет логирования просмотра медицинских карт | ❌ Не соответствует |

## Проблемные зоны

### Критические проблемы (требуют немедленного решения)

#### 1. Хранение медицинских карт на общем диске
**Описание проблемы:**
- Медицинские карты в формате сканов (JPG, PDF) хранятся на общем диске
- Любой сотрудник с доступом к сети может просмотреть любую медицинскую карту
- Нет контроля, кто и когда просматривал карты
- Нет шифрования данных

**Риски:**
- Утечка медицинских данных
- Нарушение врачебной тайны
- Нарушение 152-ФЗ
- Репутационные потери
- Штрафы от Роскомнадзора

**Приоритет:** Критический

#### 2. Отсутствие разграничения доступа к данным
**Описание проблемы:**
- Все Excel-файлы с персональными данными доступны всем сотрудникам
- Нет системы ролей и прав доступа
- Сотрудник склада может просмотреть медицинские карты пациентов
- Кассир может просмотреть данные о зарплате всех сотрудников

**Риски:**
- Несанкционированный доступ к данным
- Нарушение принципа минимальных привилегий
- Утечка данных
- Нарушение законодательства

**Приоритет:** Критический

#### 3. Отсутствие шифрования данных
**Описание проблемы:**
- Все данные хранятся в открытом виде
- Данные передаются по незащищённым каналам связи
- Нет шифрования при хранении на диске
- Нет шифрования при передаче между системами

**Риски:**
- Перехват данных при передаче
- Доступ к данным при компрометации сервера
- Нарушение требований законодательства
- Утечка данных

**Приоритет:** Критический

#### 4. Отсутствие аудита доступа к данным
**Описание проблемы:**
- Нет логирования операций с данными
- Невозможно отследить, кто и когда просматривал конфиденциальные данные
- Нет мониторинга нетипичных действий
- Нет алертинга при подозрительной активности

**Риски:**
- Невозможность расследования инцидентов
- Невозможность выявления утечек
- Нарушение требований законодательства
- Отсутствие доказательств при проверках

**Приоритет:** Критический

### Высокие проблемы (требуют решения в ближайшее время)

#### 5. Дублирование данных в разных системах
**Описание проблемы:**
- Данные о платежах хранятся и в Excel, и в 1С
- Нет единого источника истины
- Риск рассинхронизации данных
- Сложность обеспечения консистентности

**Риски:**
- Ошибки в данных
- Сложность поддержки
- Нарушение целостности данных
- Увеличение поверхности атаки

**Приоритет:** Высокий

#### 6. Использование небезопасных протоколов
**Описание проблемы:**
- Интеграция ККМ с 1С через OLE и незащищённый TCP/IP
- Нет шифрования при передаче данных
- Уязвимость к перехвату данных
- Отсутствие аутентификации

**Риски:**
- Перехват данных при передаче
- Подмена данных
- Компрометация систем
- Нарушение целостности данных

**Приоритет:** Высокий

#### 7. Отсутствие резервного копирования
**Описание проблемы:**
- Нет автоматического резервного копирования
- Риск потери данных при сбоях
- Нет плана восстановления
- Резервные копии не шифруются (если есть)

**Риски:**
- Потеря данных
- Невозможность восстановления
- Нарушение доступности данных
- Бизнес-риски

**Приоритет:** Высокий

#### 8. Отсутствие политики удаления данных
**Описание проблемы:**
- Нет правил хранения данных
- Данные хранятся бессрочно
- Нет механизма удаления данных по запросу субъекта
- Нарушение принципа минимизации данных

**Риски:**
- Нарушение прав субъектов данных
- Нарушение законодательства
- Накопление избыточных данных
- Увеличение рисков утечки

**Приоритет:** Высокий

### Средние проблемы (требуют решения в плановом порядке)

#### 9. Отсутствие классификации данных
**Описание проблемы:**
- Нет классификации данных по уровню конфиденциальности
- Все данные обрабатываются одинаково
- Невозможно применить дифференцированные меры защиты

**Риски:**
- Неоптимальное использование ресурсов
- Сложность управления защитой
- Нарушение принципа Privacy By Design

**Приоритет:** Средний

#### 10. Отсутствие механизма тегирования данных
**Описание проблемы:**
- Нет системы тегирования конфиденциальных данных
- Невозможно автоматически определить тип данных
- Нет автоматической проверки при разработке

**Риски:**
- Случайное разглашение данных
- Нарушение требований при разработке
- Сложность аудита

**Приоритет:** Средний

#### 11. Отсутствие многофакторной аутентификации
**Описание проблемы:**
- Только парольная аутентификация
- Нет дополнительных факторов защиты
- Уязвимость к компрометации учётных записей

**Риски:**
- Несанкционированный доступ
- Компрометация учётных записей
- Утечка данных

**Приоритет:** Средний

#### 12. Отсутствие системы мониторинга
**Описание проблемы:**
- Нет мониторинга доступа к данным
- Нет обнаружения аномалий
- Нет алертинга при подозрительной активности

**Риски:**
- Позднее обнаружение инцидентов
- Невозможность предотвращения утечек
- Нарушение требований безопасности

**Приоритет:** Средний

## Выводы

Текущее состояние безопасности данных в компании "Медикаменте" **не соответствует** требованиям российского законодательства и лучшим практикам информационной безопасности. Выявлено **12 критических и высоких проблем**, которые создают значительные риски утечки конфиденциальных данных.

**Основные проблемы:**
- Отсутствие базовых мер защиты (шифрование, разграничение доступа)
- Отсутствие контроля и аудита операций с данными
- Хранение особо чувствительных медицинских данных в незащищённом виде
- Использование небезопасных протоколов и методов передачи данных

**Необходимые действия:**
1. Немедленно внедрить шифрование данных при хранении и передаче
2. Внедрить систему разграничения доступа на основе ролей (RBAC)
3. Внедрить систему аудита и логирования всех операций с данными
4. Переместить медицинские карты в защищённое хранилище с контролем доступа
5. Внедрить безопасные протоколы передачи данных
6. Разработать и внедрить политику управления данными
