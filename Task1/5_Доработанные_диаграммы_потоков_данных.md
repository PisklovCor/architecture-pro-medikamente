# Доработанные диаграммы потоков данных с мерами защиты

## Введение

В данном документе представлены доработанные диаграммы потоков данных с указанием мер защиты, которые должны применяться на каждом этапе обработки данных. Диаграммы показывают, как данные должны защищаться при хранении, передаче и обработке.

## Обозначения мер защиты

- **[ENC]** - Шифрование данных
- **[AUTH]** - Аутентификация
- **[AUTHZ]** - Авторизация (контроль доступа)
- **[AUDIT]** - Аудит и логирование
- **[TAG]** - Тегирование данных
- **[MASK]** - Маскирование данных
- **[ANON]** - Обезличивание данных
- **[DLP]** - Data Loss Prevention
- **[MFA]** - Многофакторная аутентификация
- **[TLS]** - Защищённое соединение

## Доработанная диаграмма 1: Процесс записи пациента на приём

### Контекстная диаграмма (DFD Level 0)

```
[Пациент] --(ФИО, телефон, дата рождения) [TLS]--> [Портал записи]
[Портал записи] [AUTH][AUTHZ][AUDIT] --(Зашифрованные данные) [ENC]--> [База данных пациентов]
[Портал записи] [TAG] --(Тегированные данные)--> [База данных пациентов]
[Сотрудник ресепшена] [MFA][AUTH] <--(Данные о записи) [AUDIT]-- [Портал записи]
[Сотрудник ресепшена] [AUTHZ] --(Ввод данных) [AUDIT]--> [Портал записи]
[База данных пациентов] [ENC] --(Зашифрованное хранилище)--> [Хранилище]
```

### Детальная диаграмма (DFD Level 1)

```
Процесс: Запись пациента на приём с защитой

1.1 [Пациент] --(Персональные данные) [TLS 1.3]--> [Процесс 1.1: Приём данных]
1.2 [Процесс 1.1] [DLP] --(Проверка на конфиденциальность)--> [Процесс 1.2: Валидация и тегирование]
1.3 [Процесс 1.2] [TAG] --(Присвоение тегов: CONFIDENTIAL_PII_PATIENT)--> [Процесс 1.3: Шифрование]
1.4 [Процесс 1.3] [ENC: AES-256] --(Зашифрованные данные)--> [D1: База данных пациентов (PostgreSQL с TDE)]
1.5 [Процесс 1.3] [AUDIT] --(Лог операции)--> [D2: Система аудита (ELK Stack)]
1.6 [Сотрудник ресепшена] [MFA] --(Аутентификация)--> [Процесс 1.4: Проверка доступа]
1.7 [Процесс 1.4] [AUTHZ: RBAC] --(Проверка роли "Ресепшен")--> [Процесс 1.5: Получение данных]
1.8 [Процесс 1.5] [ENC: Расшифровка] --> [D1: База данных пациентов]
1.9 [Процесс 1.5] [MASK] --(Маскирование телефона: ***1234)--> [Сотрудник ресепшена]
1.10 [Процесс 1.5] [AUDIT] --(Лог доступа)--> [D2: Система аудита]
1.11 [Процесс 1.3] --(Подтверждение записи) [TLS]--> [Пациент]

Хранилища данных:
D1: База данных пациентов (PostgreSQL с TDE, шифрование AES-256)
D2: Система аудита (ELK Stack для логирования всех операций)
```

### Описание мер защиты:

1. **Приём данных** - TLS 1.3 для защиты передачи данных от пациента
2. **Валидация и тегирование** - DLP проверяет данные, автоматически присваиваются теги
3. **Шифрование** - данные шифруются AES-256 перед сохранением
4. **Проверка доступа** - MFA для сотрудников, RBAC для проверки прав
5. **Маскирование** - чувствительные данные маскируются при отображении
6. **Аудит** - все операции логируются в централизованную систему

## Доработанная диаграмма 2: Процесс приёма пациента и ведения медицинской карты

### Контекстная диаграмма (DFD Level 0)

```
[Пациент] --(Медицинские данные) [TLS]--> [Система ведения медицинских карт]
[Медицинский специалист] [MFA][AUTHZ] <--(Данные пациента) [AUDIT]-- [Система ведения медицинских карт]
[Медицинский специалист] [AUTHZ] --(Диагноз, назначения) [ENC][TAG]--> [Система ведения медицинских карт]
[Система ведения медицинских карт] [ENC] --(Зашифрованная медицинская карта)--> [Защищённое хранилище медицинских карт]
[Система ведения медицинских карт] [AUDIT] --(Логи операций)--> [Система аудита]
```

### Детальная диаграмма (DFD Level 1)

```
Процесс: Приём пациента и ведение медицинской карты с защитой

2.1 [Медицинский специалист] [MFA] --(Аутентификация)--> [Процесс 2.1: Аутентификация]
2.2 [Процесс 2.1] [AUTHZ: RBAC] --(Проверка роли "Врач")--> [Процесс 2.2: Запрос данных пациента]
2.3 [Процесс 2.2] [AUTHZ] --(Проверка: доступ только к своим пациентам)--> [D1: База данных пациентов]
2.4 [D1: База данных пациентов] [ENC: Расшифровка] --(Данные пациента)--> [Процесс 2.2]
2.5 [Процесс 2.2] [AUDIT] --(Лог доступа к данным)--> [D3: Система аудита]
2.6 [Процесс 2.2] --(Данные пациента)--> [Медицинский специалист]
2.7 [Медицинский специалист] --(Результаты осмотра, диагноз)--> [Процесс 2.3: Оформление медицинской карты]
2.8 [Процесс 2.3] [TAG] --(Тег: TOP_SECRET_PHI_PATIENT_MEDIUM_MEDICAL_SECRECY)--> [Процесс 2.4: Шифрование]
2.9 [Процесс 2.4] [ENC: AES-256] --(Зашифрованная карта)--> [D2: Защищённое хранилище медицинских карт]
2.10 [Процесс 2.4] [ENC: Цифровая подпись] --(Подписанная карта)--> [D2: Защищённое хранилище]
2.11 [Процесс 2.4] [AUDIT] --(Лог создания/изменения карты)--> [D3: Система аудита]
2.12 [Процесс 2.4] [VERSION] --(Версионирование)--> [D2: Защищённое хранилище]
2.13 [Процесс 2.4] --(Подтверждение сохранения)--> [Медицинский специалист]

Хранилища данных:
D1: База данных пациентов (PostgreSQL с TDE)
D2: Защищённое хранилище медицинских карт (объектное хранилище с шифрованием, например MinIO с шифрованием)
D3: Система аудита (ELK Stack)
```

### Описание мер защиты:

1. **Аутентификация** - MFA для медицинских специалистов
2. **Авторизация** - RBAC с проверкой роли и доступа только к своим пациентам
3. **Тегирование** - автоматическое присвоение тега TOP_SECRET для медицинских данных
4. **Шифрование** - AES-256 для всех медицинских данных
5. **Цифровая подпись** - подписание медицинских карт для обеспечения целостности
6. **Версионирование** - сохранение всех версий медицинских карт
7. **Аудит** - детальное логирование всех операций с медицинскими данными

## Доработанная диаграмма 3: Процесс обработки анализов

### Контекстная диаграмма (DFD Level 0)

```
[Лаборатория] --(Результаты анализов) [TLS][API_KEY]--> [API Gateway]
[API Gateway] [AUTH][AUTHZ][DLP] --(Проверенные данные) [ENC][TAG]--> [Система обработки анализов]
[Система обработки анализов] [ENC] --(Зашифрованные результаты)--> [Хранилище анализов]
[Медицинский специалист] [MFA][AUTHZ] <--(Результаты анализов) [MASK]-- [Система обработки анализов]
[Пациент] [AUTH] <--(Только свои результаты) [TLS][MASK]-- [Система обработки анализов]
```

### Детальная диаграмма (DFD Level 1)

```
Процесс: Обработка анализов с защитой

3.1 [Лаборатория] --(Результаты анализов) [TLS 1.3]--> [Процесс 3.1: API Gateway]
3.2 [Процесс 3.1] [AUTH: API Key] --(Проверка ключа лаборатории)--> [Процесс 3.2: Валидация данных]
3.3 [Процесс 3.2] [DLP] --(Проверка на конфиденциальность)--> [Процесс 3.3: Тегирование]
3.4 [Процесс 3.3] [TAG] --(Тег: TOP_SECRET_PHI_PATIENT_SHORT_MEDICAL_SECRECY)--> [Процесс 3.4: Шифрование]
3.5 [Процесс 3.4] [ENC: AES-256] --(Зашифрованные результаты)--> [D1: Хранилище анализов (PostgreSQL с TDE)]
3.6 [Процесс 3.4] [AUDIT] --(Лог получения результатов)--> [D2: Система аудита]
3.7 [Процесс 3.5: Уведомление специалиста] [AUTHZ: RBAC] --(Проверка роли "Врач")--> [D1: Хранилище анализов]
3.8 [Процесс 3.5] [NOTIFICATION] --(Уведомление) [TLS]--> [Медицинский специалист]
3.9 [Медицинский специалист] [MFA] --(Аутентификация)--> [Процесс 3.6: Получение результатов]
3.10 [Процесс 3.6] [AUTHZ] --(Проверка доступа к пациенту)--> [D1: Хранилище анализов]
3.11 [D1: Хранилище анализов] [ENC: Расшифровка] --(Результаты)--> [Процесс 3.6]
3.12 [Процесс 3.6] [AUDIT] --(Лог доступа)--> [D2: Система аудита]
3.13 [Процесс 3.6] --(Результаты)--> [Медицинский специалист]
3.14 [Пациент] [AUTH] --(Аутентификация)--> [Процесс 3.7: Получение своих результатов]
3.15 [Процесс 3.7] [AUTHZ] --(Проверка: только свои данные)--> [D1: Хранилище анализов]
3.16 [D1: Хранилище анализов] [ENC: Расшифровка] --(Результаты)--> [Процесс 3.7]
3.17 [Процесс 3.7] [MASK] --(Маскирование идентификаторов)--> [Пациент]
3.18 [Процесс 3.7] [AUDIT] --(Лог доступа пациента)--> [D2: Система аудита]
3.19 [Процесс 3.8: Автоматическое удаление] [RETENTION] --(Удаление после истечения срока)--> [D1: Хранилище анализов]

Хранилища данных:
D1: Хранилище анализов (PostgreSQL с TDE, автоматическое удаление по политике)
D2: Система аудита (ELK Stack)
```

### Описание мер защиты:

1. **API Gateway** - централизованная точка входа с аутентификацией по API ключам
2. **DLP** - проверка данных на конфиденциальность при получении
3. **Тегирование** - автоматическое присвоение тега TOP_SECRET для результатов анализов
4. **Шифрование** - AES-256 для всех медицинских данных
5. **Контроль доступа** - строгий RBAC, пациенты видят только свои данные
6. **Маскирование** - маскирование идентификаторов при выдаче пациенту
7. **Автоматическое удаление** - удаление данных после истечения срока хранения
8. **Аудит** - логирование всех операций с результатами анализов

## Доработанная диаграмма 4: Процесс приёма платежей

### Контекстная диаграмма (DFD Level 0)

```
[Пациент] --(Оплата услуг) [TLS][PCI_DSS]--> [Платёжный шлюз]
[Платёжный шлюз] [ENC][MASK] --(Зашифрованные данные) [TLS]--> [Система приёма платежей]
[Кассир] [MFA][AUTHZ] <--(Данные об оплате) [MASK]-- [Система приёма платежей]
[Система приёма платежей] [ENC][TAG] --(Зашифрованные данные)--> [1С:Бухгалтерия]
[Система приёма платежей] [ENC][TAG] --(Зашифрованные данные)--> [База данных платежей]
[ККМ] [TLS] <--> [Система приёма платежей]
```

### Детальная диаграмма (DFD Level 1)

```
Процесс: Приём платежей с защитой

4.1 [Пациент] --(Данные карты) [TLS 1.3]--> [Процесс 4.1: Платёжный шлюз]
4.2 [Процесс 4.1] [PCI_DSS] --(Соответствие PCI DSS)--> [Процесс 4.2: Обработка платежа]
4.3 [Процесс 4.2] [ENC: Tokenization] --(Токенизация данных карты)--> [Процесс 4.3: Сохранение]
4.4 [Процесс 4.3] [TAG] --(Тег: RESTRICTED_FINANCIAL_CONTRACT_MEDIUM_PCI_DSS)--> [D1: База данных платежей]
4.5 [Процесс 4.3] [ENC: AES-256] --(Зашифрованные данные)--> [D1: База данных платежей]
4.6 [Кассир] [MFA] --(Аутентификация)--> [Процесс 4.4: Формирование чека]
4.7 [Процесс 4.4] [AUTHZ: RBAC] --(Проверка роли "Кассир")--> [Процесс 4.5: Интеграция с ККМ]
4.8 [Процесс 4.5] [TLS] --(Защищённое соединение)--> [ККМ]
4.9 [ККМ] --(Чек) [TLS]--> [Процесс 4.5]
4.10 [Процесс 4.5] [MASK] --(Маскирование данных карты в чеке)--> [Пациент]
4.11 [Процесс 4.6: Интеграция с 1С] [ENC] --(Зашифрованные данные) [TLS]--> [1С:Бухгалтерия]
4.12 [Процесс 4.6] [AUDIT] --(Лог передачи данных)--> [D2: Система аудита]
4.13 [Процесс 4.3] [AUDIT] --(Лог операции)--> [D2: Система аудита]

Хранилища данных:
D1: База данных платежей (PostgreSQL с TDE, соответствие PCI DSS)
D2: Система аудита (ELK Stack)
```

### Описание мер защиты:

1. **TLS 1.3** - защищённое соединение для всех передач данных
2. **PCI DSS** - соответствие стандартам безопасности платёжных данных
3. **Tokenization** - замена данных карты на токены
4. **Тегирование** - присвоение тега RESTRICTED для финансовых данных
5. **Шифрование** - AES-256 для всех финансовых данных
6. **Маскирование** - маскирование данных карты в чеках и интерфейсах
7. **Контроль доступа** - RBAC для кассиров
8. **Аудит** - детальное логирование всех финансовых операций

## Доработанная диаграмма 5: Процесс бухгалтерского учёта

### Контекстная диаграмма (DFD Level 0)

```
[Бухгалтер] [MFA][AUTHZ] <--(Финансовые данные) [MASK]-- [Система бухгалтерского учёта]
[Бухгалтер] [AUTHZ] --(Ввод данных) [ENC][AUDIT]--> [Система бухгалтерского учёта]
[Система бухгалтерского учёта] [ENC][TAG] <--> [1С:Бухгалтерия]
[Система бухгалтерского учёта] [ENC][TLS] --(Зашифрованные отчёты)--> [Налоговые органы]
[Система бухгалтерского учёта] [MASK] --(Маскированные данные)--> [Сотрудники]
```

### Детальная диаграмма (DFD Level 1)

```
Процесс: Бухгалтерский учёт с защитой

5.1 [Бухгалтер] [MFA] --(Аутентификация)--> [Процесс 5.1: Аутентификация]
5.2 [Процесс 5.1] [AUTHZ: RBAC] --(Проверка роли "Бухгалтер")--> [Процесс 5.2: Обработка платежей]
5.3 [Процесс 5.2] [ENC] --(Зашифрованные данные) [TLS]--> [D1: 1С:Бухгалтерия (с шифрованием)]
5.4 [Процесс 5.2] [TAG] --(Тег: CONFIDENTIAL_FINANCIAL)--> [D1: 1С:Бухгалтерия]
5.5 [Процесс 5.2] [AUDIT] --(Лог операции)--> [D2: Система аудита]
5.6 [Бухгалтер] --(Кадровые данные)--> [Процесс 5.3: Учёт кадров]
5.7 [Процесс 5.3] [ENC] [TAG: RESTRICTED_PII_EMPLOYEE] --> [D1: 1С:Бухгалтерия]
5.8 [Процесс 5.3] [AUDIT] --> [D2: Система аудита]
5.9 [Процесс 5.4: Начисление зарплаты] [ENC] --> [D1: 1С:Бухгалтерия]
5.10 [Процесс 5.4] [MASK] --(Маскированные данные о зарплате)--> [Сотрудники]
5.11 [Процесс 5.4] [AUDIT] --> [D2: Система аудита]
5.12 [Бухгалтер] --(Формирование отчётов)--> [Процесс 5.5: Подготовка отчётов]
5.13 [Процесс 5.5] [ENC] [TLS] --(Зашифрованные отчёты)--> [Налоговые органы]
5.14 [Процесс 5.5] [AUDIT] --> [D2: Система аудита]

Хранилища данных:
D1: 1С:Бухгалтерия (с шифрованием базы данных)
D2: Система аудита (ELK Stack)
```

### Описание мер защиты:

1. **MFA** - многофакторная аутентификация для бухгалтеров
2. **RBAC** - строгий контроль доступа на основе ролей
3. **Шифрование** - шифрование всех финансовых и кадровых данных
4. **Тегирование** - автоматическое тегирование данных по типу
5. **Маскирование** - маскирование данных о зарплате при выдаче сотрудникам
6. **TLS** - защищённая передача отчётов в налоговые органы
7. **Аудит** - логирование всех финансовых операций

## Доработанная диаграмма 6: Процесс передачи данных в BI/ML/AI системы

### Контекстная диаграмма (DFD Level 0)

```
[Операционные системы] [ENC][TAG] --(Тегированные данные)--> [Процесс обезличивания]
[Процесс обезличивания] [ANON][MASK] --(Обезличенные данные)--> [Data Lake]
[Data Lake] [ENC][TAG] --(Зашифрованные данные)--> [BI системы]
[Data Lake] [ENC][TAG] --(Зашифрованные данные)--> [ML/AI системы]
[Аналитики] [AUTHZ] <--(Обезличенные данные) [AUDIT]-- [BI системы]
```

### Детальная диаграмма (DFD Level 1)

```
Процесс: Передача данных в BI/ML/AI с защитой

6.1 [Операционные системы] [ENC] --(Зашифрованные данные)--> [Процесс 6.1: Извлечение данных]
6.2 [Процесс 6.1] [TAG] --(Чтение тегов данных)--> [Процесс 6.2: Классификация данных]
6.3 [Процесс 6.2] --(Определение уровня конфиденциальности)--> [Процесс 6.3: Применение политик]
6.4 [Процесс 6.3] [ANON] --(Обезличивание PII)--> [Процесс 6.4: Подготовка данных]
6.5 [Процесс 6.4] [MASK] --(Маскирование идентификаторов)--> [Процесс 6.5: Токенизация]
6.6 [Процесс 6.5] [ENC: AES-256] --(Зашифрованные обезличенные данные)--> [D1: Data Lake (MinIO с шифрованием)]
```
