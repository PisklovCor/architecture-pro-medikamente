# План улучшений безопасности данных

## Введение

В данном документе представлен план улучшений безопасности данных для компании "Медикаменте", включающий способы защиты данных, механизм тегирования и список необходимых инструментов и мер.

## Список данных для защиты и способы защиты

### Категория 1: Критически конфиденциальные медицинские данные

#### 1.1 Хронические заболевания
- **Способ защиты:** Шифрование + Обезличивание + Обфускация
- **Шифрование:** AES-256 при хранении, TLS 1.3 при передаче
- **Обезличивание:** Замена конкретных диагнозов на категории при аналитике
- **Обфускация:** Хеширование идентификаторов при передаче в BI-системы
- **Дополнительно:** Строгий контроль доступа (только лечащие врачи), детальный аудит

#### 1.2 Результаты анализов
- **Способ защиты:** Шифрование + Обезличивание
- **Шифрование:** AES-256 при хранении, TLS 1.3 при передаче
- **Обезличивание:** Удаление персональных идентификаторов при использовании в ML/AI
- **Дополнительно:** Контроль доступа, сроки хранения, автоматическое удаление после истечения срока

#### 1.3 Медицинские диагнозы
- **Способ защиты:** Шифрование + Обфускация
- **Шифрование:** AES-256 при хранении
- **Обфускация:** Кодирование диагнозов по МКБ-10 вместо текстового описания
- **Дополнительно:** Доступ только для медицинских специалистов, аудит всех операций

#### 1.4 Полные медицинские карты
- **Способ защиты:** Шифрование + Контроль доступа + Аудит
- **Шифрование:** AES-256 при хранении, шифрование файлов на диске
- **Контроль доступа:** RBAC с ролями (лечащий врач, администратор, пациент - только свои данные)
- **Аудит:** Логирование всех операций чтения, изменения, удаления
- **Дополнительно:** Цифровые подписи, версионирование, резервное копирование с шифрованием

### Категория 2: Высококонфиденциальные персональные данные

#### 2.1 ФИО + Дата рождения
- **Способ защиты:** Шифрование + Обфускация
- **Шифрование:** AES-256 при хранении в БД
- **Обфускация:** Токенизация при использовании в аналитике
- **Дополнительно:** Контроль доступа, минимизация данных (собирать только необходимое)

#### 2.2 Адрес прописки
- **Способ защиты:** Шифрование + Обезличивание
- **Шифрование:** AES-256 при хранении
- **Обезличивание:** Замена точного адреса на район/город при аналитике
- **Дополнительно:** Доступ только для сотрудников ресепшена и бухгалтерии

#### 2.3 Финансовые данные о платежах
- **Способ защиты:** Шифрование + Обфускация + Контроль доступа
- **Шифрование:** AES-256 при хранении, TLS при передаче
- **Обфускация:** Маскирование номеров карт (показывать только последние 4 цифры)
- **Контроль доступа:** Доступ только для кассиров и бухгалтеров
- **Дополнительно:** PCI DSS compliance, детальный аудит

#### 2.4 Место работы или учёбы
- **Способ защиты:** Шифрование + Обезличивание
- **Шифрование:** AES-256 при хранении
- **Обезличивание:** Замена на категорию (работает/учится/безработный) при аналитике
- **Дополнительно:** Минимизация данных (собирать только при необходимости)

### Категория 3: Конфиденциальные данные

#### 3.1 Телефон
- **Способ защиты:** Шифрование + Обфускация
- **Шифрование:** AES-256 при хранении
- **Обфускация:** Маскирование (показывать только последние 4 цифры в интерфейсах)
- **Дополнительно:** Контроль доступа, использование для связи только авторизованными сотрудниками

#### 3.2 Электронная почта
- **Способ защиты:** Шифрование + Обфускация
- **Шифрование:** AES-256 при хранении, TLS при передаче
- **Обфускация:** Маскирование (показывать только домен или первые буквы)
- **Дополнительно:** Контроль доступа, защита от спама

#### 3.3 Данные о записях на приём
- **Способ защиты:** Шифрование + Контроль доступа
- **Шифрование:** AES-256 при хранении
- **Контроль доступа:** Доступ для ресепшена, медицинских специалистов и пациента (только свои записи)
- **Дополнительно:** Аудит изменений записей

#### 3.4 Общая информация о пациентах
- **Способ защиты:** Шифрование + Контроль доступа
- **Шифрование:** AES-256 при хранении
- **Контроль доступа:** RBAC с ролями
- **Дополнительно:** Минимизация данных в отчётах

## Механизм тегирования данных

### Система тегов для классификации данных

#### Уровень конфиденциальности (Confidentiality Level)
- **PUBLIC** - Публичные данные, не требующие защиты
- **INTERNAL** - Внутренние данные, доступные сотрудникам
- **CONFIDENTIAL** - Конфиденциальные данные, требующие защиты
- **RESTRICTED** - Ограниченные данные, строгий контроль доступа
- **TOP_SECRET** - Особо секретные данные (медицинские диагнозы, результаты анализов)

#### Тип данных (Data Type)
- **PII** - Персональные идентифицирующие данные (ФИО, паспорт)
- **PHI** - Защищённая медицинская информация (диагнозы, анализы)
- **FINANCIAL** - Финансовые данные (платежи, счета)
- **CONTACT** - Контактная информация (телефон, email)
- **DEMOGRAPHIC** - Демографические данные (возраст, адрес)

#### Категория субъекта (Subject Category)
- **PATIENT** - Данные пациента
- **EMPLOYEE** - Данные сотрудника
- **CONTRACT** - Данные договора
- **MEDICAL** - Медицинские данные

#### Срок хранения (Retention Period)
- **IMMEDIATE** - Удаление сразу после использования
- **SHORT** - Хранение до 1 года
- **MEDIUM** - Хранение до 5 лет
- **LONG** - Хранение до 10 лет
- **PERMANENT** - Постоянное хранение (только для архивных данных)

#### Юридические требования (Legal Requirements)
- **152_FZ** - Требования 152-ФЗ "О персональных данных"
- **MEDICAL_SECRECY** - Врачебная тайна
- **PCI_DSS** - Требования PCI DSS для финансовых данных
- **GDPR** - Требования GDPR (если применимо)

### Формат тега

Тег формируется в формате: `[Уровень]_[Тип]_[Категория]_[Срок]_[Требования]`

**Примеры тегов:**
- `TOP_SECRET_PHI_PATIENT_MEDIUM_MEDICAL_SECRECY` - Результаты анализов пациента
- `RESTRICTED_PII_PATIENT_LONG_152_FZ` - ФИО и дата рождения пациента
- `CONFIDENTIAL_FINANCIAL_CONTRACT_MEDIUM_PCI_DSS` - Данные о платежах
- `CONFIDENTIAL_CONTACT_PATIENT_SHORT_152_FZ` - Телефон пациента

### Реализация тегирования

#### 1. Тегирование на уровне базы данных
- Добавление метаданных к полям таблиц
- Использование комментариев в схеме БД для хранения тегов
- Создание отдельной таблицы метаданных с привязкой к полям

#### 2. Тегирование на уровне приложения
- Аннотации в коде (Java annotations)
- Конфигурационные файлы с описанием тегов
- Middleware для автоматического применения тегов

#### 3. Тегирование на уровне файлов
- Расширенные атрибуты файлов (Windows EFS, Linux xattr)
- Метаданные в PDF/DOCX файлах
- Система управления документами с поддержкой тегов

#### 4. Автоматическое тегирование
- Использование DLP-систем для автоматического определения типа данных
- Машинное обучение для классификации данных
- Правила на основе регулярных выражений

### Инструменты тегирования

#### 1. Apache Atlas
- **Назначение:** Управление метаданными и тегами в data lake
- **Применение:** Тегирование данных в озере данных для BI/ML/AI
- **Преимущества:** Интеграция с Hadoop, Hive, Kafka, поддержка lineage

#### 2. Collibra Data Catalog
- **Назначение:** Каталог данных с поддержкой тегирования
- **Применение:** Централизованное управление метаданными
- **Преимущества:** UI для бизнес-пользователей, автоматическое обнаружение данных

#### 3. Microsoft Purview
- **Назначение:** Управление данными и compliance
- **Применение:** Тегирование данных в облаке и on-premise
- **Преимущества:** Интеграция с Azure, автоматическое сканирование

#### 4. Собственное решение на базе Java
- **Назначение:** Кастомное решение под специфику компании
- **Применение:** Интеграция с существующими системами
- **Преимущества:** Полный контроль, соответствие требованиям

### Процесс применения тегов

1. **Идентификация данных** - определение типа и категории данных
2. **Присвоение тега** - применение соответствующего тега
3. **Валидация** - проверка корректности тега
4. **Применение политик** - автоматическое применение политик безопасности на основе тега
5. **Мониторинг** - отслеживание использования тегированных данных
6. **Аудит** - логирование всех операций с тегированными данными

## Список инструментов, способов и мер для обеспечения конфиденциальности

### Инструменты для шифрования

#### 1. Шифрование при хранении
- **PostgreSQL с pgcrypto** - шифрование данных в БД
- **Transparent Data Encryption (TDE)** - прозрачное шифрование на уровне СУБД
- **VeraCrypt / BitLocker** - шифрование дисков
- **AWS KMS / Azure Key Vault** - управление ключами шифрования
- **HashiCorp Vault** - управление секретами и ключами

#### 2. Шифрование при передаче
- **TLS 1.3** - для всех HTTP/HTTPS соединений
- **VPN** - для удалённого доступа
- **SSH** - для административного доступа
- **SFTP** - для передачи файлов
- **API Gateway с mTLS** - для межсервисного взаимодействия

### Инструменты для контроля доступа

#### 1. Аутентификация
- **Keycloak** - система управления идентификацией и доступом (IAM)
- **Active Directory** - интеграция с существующей AD
- **LDAP** - для централизованной аутентификации
- **OAuth 2.0 / OpenID Connect** - для веб-приложений
- **Многофакторная аутентификация (MFA)** - Duo, Google Authenticator, YubiKey

#### 2. Авторизация
- **RBAC (Role-Based Access Control)** - контроль доступа на основе ролей
- **ABAC (Attribute-Based Access Control)** - контроль доступа на основе атрибутов
- **Apache Ranger** - управление политиками безопасности для больших данных
- **OPA (Open Policy Agent)** - унифицированная политика доступа

### Инструменты для аудита и мониторинга

#### 1. Логирование и аудит
- **ELK Stack (Elasticsearch, Logstash, Kibana)** - централизованное логирование
- **Apache Kafka** - потоковая передача логов
- **Auditd** - аудит системных событий Linux
- **Windows Event Log** - аудит событий Windows
- **CloudTrail / Azure Monitor** - аудит облачных операций

#### 2. Мониторинг и алертинг
- **Prometheus + Grafana** - мониторинг метрик
- **Victoria Metrics** - хранение метрик (уже в стеке компании)
- **Elastic Stack** - поиск и анализ логов
- **SIEM системы** - Splunk, QRadar, ArcSight для обнаружения угроз
- **DLP системы** - предотвращение утечек данных

### Инструменты для защиты данных

#### 1. Data Loss Prevention (DLP)
- **Microsoft Purview Data Loss Prevention** - предотвращение утечек
- **Symantec DLP** - корпоративное решение DLP
- **Forcepoint DLP** - защита от утечек данных
- **McAfee DLP** - комплексная защита данных

#### 2. Маскирование и обфускация данных
- **Delphix** - виртуализация и маскирование данных
- **Informatica Persistent Data Masking** - постоянное маскирование
- **IBM InfoSphere Optim** - маскирование тестовых данных
- **Собственные скрипты** - на базе Java/Python для специфических задач

#### 3. Анонимизация данных
- **ARX** - инструмент для анонимизации данных
- **sdcMicro** - статистическое раскрытие контроля
- **Python библиотеки** - Faker, anonymizer для генерации синтетических данных

### Инструменты для управления данными

#### 1. Управление метаданными
- **Apache Atlas** - управление метаданными и lineage
- **Collibra** - каталог данных
- **Alation** - управление данными с AI
- **Microsoft Purview** - управление данными

#### 2. Data Lineage
- **Apache Atlas** - отслеживание происхождения данных
- **Collibra Lineage** - визуализация потоков данных
- **MANTA** - автоматическое построение lineage
- **Spline** - lineage для Spark

### Организационные меры

#### 1. Политики и процедуры
- **Политика информационной безопасности** - документирование правил работы с данными
- **Политика классификации данных** - правила присвоения уровней конфиденциальности
- **Политика управления доступом** - правила предоставления и отзыва доступа
- **Политика резервного копирования** - правила создания и хранения бэкапов
- **План реагирования на инциденты** - процедуры при утечке данных

#### 2. Обучение и осведомлённость
- **Обучение сотрудников** - правилам работы с конфиденциальными данными
- **Регулярные проверки** - тестирование знаний сотрудников
- **Информирование об угрозах** - регулярные рассылки о новых угрозах

#### 3. Соответствие требованиям
- **Аудит соответствия** - регулярные проверки соответствия 152-ФЗ
- **Документирование** - ведение реестра обработки персональных данных
- **Уведомление Роскомнадзора** - регистрация оператора персональных данных

### Технические меры

#### 1. Сетевая безопасность
- **Firewall** - контроль сетевого трафика
- **Network Segmentation** - разделение сетей
- **Intrusion Detection System (IDS)** - обнаружение вторжений
- **Intrusion Prevention System (IPS)** - предотвращение вторжений

#### 2. Безопасность приложений
- **Static Application Security Testing (SAST)** - статический анализ кода
- **Dynamic Application Security Testing (DAST)** - динамическое тестирование
- **Dependency Scanning** - проверка уязвимостей в зависимостях
- **Code Review** - проверка кода на безопасность

#### 3. Безопасность инфраструктуры
- **Hardening** - усиление безопасности серверов
- **Patch Management** - управление обновлениями
- **Vulnerability Scanning** - сканирование уязвимостей
- **Container Security** - безопасность контейнеров (для Kubernetes)

## Выводы

Для обеспечения конфиденциальности данных в компании "Медикаменте" необходимо внедрить комплексный подход, включающий:

1. **Технические меры** - шифрование, контроль доступа, аудит
2. **Инструменты** - DLP, системы мониторинга, управления метаданными
3. **Организационные меры** - политики, обучение, соответствие требованиям
4. **Механизм тегирования** - для автоматического применения политик безопасности

Реализация должна проводиться поэтапно с приоритетом на критические проблемы, связанные с хранением и доступом к медицинским данным.
