# Диаграмма контекста C4 целевого состояния системы "Медикаменте"

## Введение

В данном документе представлена диаграмма контекста (Context Diagram) целевого состояния системы "Медикаменте" с учётом принципов Privacy by Design. Диаграмма показывает систему на высоком уровне абстракции - как единое целое и её взаимодействие с внешними пользователями и системами.

## Описание диаграммы

### Уровень: Context (Контекст)

Диаграмма показывает систему "Медикаменте" как единый компонент и всех людей и системы, которые взаимодействуют с ней.

---

## Внешние пользователи и системы

### Люди (People)

#### 1. Пациент
- **Описание:** Клиент медицинского центра, который использует услуги компании
- **Взаимодействие:**
  - Записывается на приём через портал или мобильное приложение
  - Просматривает свои медицинские данные (анализы, заключения, договоры)
  - Управляет согласиями на обработку персональных данных
  - Может запросить доступ, исправление или удаление своих данных
- **Требования конфиденциальности:**
  - Видит только свои данные
  - Может управлять согласиями
  - Может запросить удаление данных

#### 2. Медицинский специалист
- **Описание:** Врач или другой медицинский работник, который ведёт приём пациентов
- **Взаимодействие:**
  - Просматривает медицинские карты своих пациентов
  - Вводит данные о приёме, диагнозах, назначениях
  - Просматривает результаты анализов
  - Получает уведомления о записях
- **Требования конфиденциальности:**
  - Доступ только к данным своих пациентов
  - Многофакторная аутентификация
  - Все операции аудируются

#### 3. Сотрудник ресепшена
- **Описание:** Административный сотрудник, который ведёт запись пациентов
- **Взаимодействие:**
  - Управляет записями пациентов
  - Заключает договоры с клиентами
  - Просматривает расписание специалистов
  - Отправляет напоминания пациентам
- **Требования конфиденциальности:**
  - Доступ к ограниченному набору данных (не медицинские данные)
  - Маскирование чувствительных данных при отображении
  - Аудит всех операций

#### 4. Кассир
- **Описание:** Сотрудник, который принимает платежи от пациентов
- **Взаимодействие:**
  - Принимает платежи от пациентов
  - Формирует чеки через ККМ
  - Просматривает информацию о платежах
- **Требования конфиденциальности:**
  - Доступ только к финансовым данным
  - Маскирование данных карт
  - Соответствие PCI DSS

#### 5. Бухгалтер
- **Описание:** Сотрудник бухгалтерии, который ведёт финансовый учёт
- **Взаимодействие:**
  - Обрабатывает платежи
  - Ведёт бухгалтерский учёт
  - Формирует отчёты для налоговых органов
  - Управляет кадровыми данными
- **Требования конфиденциальности:**
  - Доступ к финансовым и кадровым данным
  - Строгий контроль доступа
  - Аудит всех финансовых операций

#### 6. Сотрудник склада
- **Описание:** Сотрудник, который ведёт учёт товарно-материальных ценностей
- **Взаимодействие:**
  - Учитывает ТМЦ
  - Управляет закупками оборудования
  - Интегрируется с 1С:Торговля и склад
- **Требования конфиденциальности:**
  - Доступ только к данным о ТМЦ
  - Ограниченный доступ к другим данным

#### 7. Аналитик
- **Описание:** Бизнес-аналитик или сотрудник, который работает с аналитическими данными
- **Взаимодействие:**
  - Строит отчёты на основе обезличенных данных
  - Анализирует бизнес-метрики
  - Работает с BI-системами
- **Требования конфиденциальности:**
  - Доступ только к обезличенным данным
  - Нет доступа к персональным данным
  - Аудит всех аналитических запросов

#### 8. Технический директор / Администратор
- **Описание:** IT-специалисты, которые управляют системой
- **Взаимодействие:**
  - Управляют системой
  - Настраивают политики конфиденциальности
  - Мониторят безопасность
  - Просматривают аудит-логи
- **Требования конфиденциальности:**
  - Привилегированный доступ с многофакторной аутентификацией
  - Все операции логируются
  - Принцип минимальных привилегий

### Внешние системы (External Systems)

#### 1. Лаборатория анализов
- **Описание:** Внешняя лаборатория, которая выполняет анализы для пациентов
- **Взаимодействие:**
  - Передаёт результаты анализов через API
  - Получает информацию о назначенных анализах
- **Требования конфиденциальности:**
  - Аутентификация по API ключам
  - Шифрование всех передач данных (TLS)
  - Передача только необходимых данных
  - Аудит всех операций

#### 2. Платёжный провайдер
- **Описание:** Внешний сервис для обработки платежей (например, банк или платёжная система)
- **Взаимодействие:**
  - Обрабатывает платежи от пациентов
  - Возвращает результаты обработки платежей
- **Требования конфиденциальности:**
  - Соответствие PCI DSS
  - Шифрование всех передач
  - Токенизация данных карт
  - Аудит всех транзакций

#### 3. 1С:Бухгалтерия предприятия
- **Описание:** Существующая система бухгалтерского учёта
- **Взаимодействие:**
  - Получает данные о платежах
  - Передаёт данные о начислении зарплаты
  - Интегрируется с системой учёта
- **Требования конфиденциальности:**
  - Шифрование передач данных
  - Контроль доступа к данным
  - Аудит интеграций

#### 4. 1С:Торговля и склад
- **Описание:** Существующая система учёта ТМЦ
- **Взаимодействие:**
  - Получает данные о закупках
  - Передаёт данные о наличии ТМЦ
- **Требования конфиденциальности:**
  - Шифрование передач данных
  - Контроль доступа

#### 5. ККМ (Контрольно-кассовые машины)
- **Описание:** Физические устройства для печати чеков
- **Взаимодействие:**
  - Получает данные о платежах для печати чеков
  - Передаёт данные о напечатанных чеках
- **Требования конфиденциальности:**
  - Защищённое соединение (TLS)
  - Маскирование данных в чеках
  - Аудит операций

#### 6. Налоговые органы
- **Описание:** Государственные органы, которые получают налоговую отчётность
- **Взаимодействие:**
  - Получает налоговую отчётность
  - Получает данные о платежах (при необходимости)
- **Требования конфиденциальности:**
  - Шифрование передач данных
  - Передача только необходимых данных
  - Аудит всех передач

#### 7. Мобильное приложение (клиентское)
- **Описание:** Мобильное приложение для пациентов
- **Взаимодействие:**
  - Пациенты записываются на приём
  - Просматривают свои данные
  - Получают уведомления
  - Управляют согласиями
- **Требования конфиденциальности:**
  - Шифрование всех передач (TLS)
  - Аутентификация пользователей
  - Доступ только к своим данным
  - Локальное шифрование данных

## Система "Медикаменте" (целевое состояние)

### Описание системы

Единая автоматизированная система управления медицинским центром, которая обеспечивает:

1. **Управление пациентами и записями**
   - Портал для записи пациентов
   - Управление медицинскими картами
   - Интеграция с лабораторией

2. **Финансовое управление**
   - Приём платежей
   - Интеграция с бухгалтерией
   - Управление договорами

3. **Управление ресурсами**
   - Учёт ТМЦ
   - Управление расписанием специалистов

4. **Аналитика**
   - BI-отчёты
   - ML/AI системы
   - Анализ данных

5. **Защита конфиденциальности**
   - Privacy by Design на всех уровнях
   - Автоматическая защита данных
   - Управление согласиями
   - Аудит всех операций

## Взаимодействия на диаграмме контекста

### Взаимодействия с пациентами:

```
Пациент ←→ Система "Медикаменте"
- Запись на приём (HTTPS/TLS)
- Просмотр своих данных (HTTPS/TLS, аутентификация)
- Управление согласиями (HTTPS/TLS)
- Запросы на доступ/исправление/удаление данных (HTTPS/TLS)
```

Медицинский специалист ←→ Система "Медикаменте"

- Просмотр результатов анализов (HTTPS/TLS, MFA, RBAC)

Сотрудник ресепшена ←→ Система "Медикаменте"
- Управление записями (HTTPS/TLS, MFA, RBAC)
- Заключение договоров (HTTPS/TLS, MFA, RBAC, аудит)

Кассир ←→ Система "Медикаменте"
- Приём платежей (HTTPS/TLS, MFA, RBAC, PCI DSS)
- Формирование чеков (HTTPS/TLS, MFA, RBAC)

Бухгалтер ←→ Система "Медикаменте"
- Бухгалтерский учёт (HTTPS/TLS, MFA, RBAC, аудит)
- Формирование отчётов (HTTPS/TLS, MFA, RBAC)

Сотрудник склада ←→ Система "Медикаменте"
- Учёт ТМЦ (HTTPS/TLS, MFA, RBAC)

Аналитик ←→ Система "Медикаменте"
- Работа с BI-системами (HTTPS/TLS, MFA, RBAC, только обезличенные данные)
- Построение отчётов (HTTPS/TLS, MFA, RBAC)

Технический директор ←→ Система "Медикаменте"
- Управление системой (HTTPS/TLS, MFA, привилегированный доступ)
- Настройка политик (HTTPS/TLS, MFA, привилегированный доступ)
- Мониторинг безопасности (HTTPS/TLS, MFA, привилегированный доступ)
```

```

1С:Бухгалтерия ↔ Система "Медикаменте"

1С:Торговля и склад ↔ Система "Медикаменте"
- Синхронизация данных о ТМЦ (HTTPS/TLS, шифрование, аудит)

ККМ ↔ Система "Медикаменте"
- Печать чеков (TLS, маскирование данных, аудит)

Налоговые органы ← Система "Медикаменте"

## Ключевые характеристики системы

### Безопасность и конфиденциальность:

1. **Шифрование везде**
   - Все передачи данных через TLS 1.3
   - Шифрование данных при хранении (AES-256)
   - Управление ключами через централизованный сервис

2. **Контроль доступа**
   - Многофакторная аутентификация для всех пользователей
   - Role-Based Access Control (RBAC)
   - Attribute-Based Access Control (ABAC) для сложных сценариев
   - Принцип минимальных привилегий

3. **Аудит и мониторинг**
   - Все операции логируются
   - Централизованное хранение логов
   - Невозможность удаления или изменения логов аудита
   - Автоматическое обнаружение аномалий

4. **Защита данных**
   - Автоматическое тегирование данных
   - Маскирование чувствительных данных при отображении
   - Обезличивание данных для аналитики
   - Автоматическое удаление данных по истечении срока

5. **Прозрачность**
   - Пользователи видят, как обрабатываются их данные
   - Пользователи могут управлять согласиями
   - Пользователи могут запросить доступ, исправление или удаление данных

### Масштабируемость:

1. **Горизонтальное масштабирование**
   - Микросервисная архитектура
   - Возможность добавления узлов
   - Балансировка нагрузки

2. **Масштабирование данных**
   - Data Lake для аналитики
   - Партиционирование данных
   - Кэширование часто используемых данных

3. **Масштабирование пользователей**
   - Поддержка роста числа пользователей
   - Поддержка новых филиалов
   - Поддержка мобильных пользователей

### Интеграции:

1. **API-first подход**
   - Все интеграции через API
   - Версионирование API
   - Документация API

2. **Безопасные интеграции**
   - Аутентификация по API ключам
   - Шифрование всех передач
   - Аудит всех интеграций

3. **Гибкость**
   - Легкое добавление новых интеграций
   - Поддержка различных форматов данных
   - Асинхронная обработка

## Визуальные диаграммы

В директории Task2 созданы следующие файлы с диаграммами:

1. **`project10-landscape-target.drawio`** - диаграмма в формате draw.io (XML)
   - Можно открыть в draw.io (diagrams.net)
   - Можно экспортировать как PNG, SVG, PDF
   - Содержит все элементы диаграммы с подписями

2. **`project10-landscape-target.puml`** - диаграмма в формате PlantUML
   - Можно сгенерировать изображение с помощью PlantUML
   - Использует библиотеку C4-PlantUML для правильного отображения C4 диаграмм
   - Можно использовать онлайн: http://www.plantuml.com/plantuml/uml/

### Инструменты для создания/редактирования:
- **draw.io** (diagrams.net) - бесплатный инструмент, открыть файл `.drawio`
- **Lucidchart** - облачный инструмент
- **PlantUML** - для генерации из `.puml` файла
- **C4-PlantUML** - расширение PlantUML для C4 (уже включено в .puml файл)

1. **Центральный компонент:**
   - Название: "Система 'Медикаменте' (Целевое состояние)"
   - Описание: "Единая автоматизированная система управления медицинским центром с Privacy by Design"

2. **Пользователи (слева):**
   - Пациент
   - Медицинский специалист
   - Сотрудник ресепшена
   - Кассир
   - Бухгалтер
   - Сотрудник склада

   - Технический директор

3. **Внешние системы (справа):**
   - Лаборатория анализов

Все связи должны показывать:

- **Зелёный** - безопасные взаимодействия с применением всех мер защиты
- **Жёлтый** - взаимодействия с частичной защитой
- **Красный** - взаимодействия, требующие дополнительной защиты

## Выводы

Диаграмма контекста целевого состояния показывает:

1. **Всех пользователей системы** - от пациентов до администраторов
2. **Все внешние системы** - от лабораторий до налоговых органов
3. **Требования безопасности** - для каждого взаимодействия
4. **Принципы Privacy by Design** - встроенные в систему

Система спроектирована с учётом:
- Защиты конфиденциальности данных
- Соответствия требованиям 152-ФЗ
- Масштабируемости для роста бизнеса
