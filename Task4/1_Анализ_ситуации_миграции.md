# Анализ ситуации миграции

## Введение

Компания "Медикаменте" планирует миграцию с устаревшей монолитной системы на современную микросервисную архитектуру. Данный документ содержит анализ текущего состояния системы, целей миграции и ключевых процессов, которые будут затронуты в процессе перехода.

## Текущее состояние системы (As-Is)

### Архитектура

Текущая система представляет собой монолитную архитектуру с несколькими изолированными компонентами:

- **Физический сервер** Windows Server 2022 в здании офиса
- **1С:Бухгалтерия предприятия** (файловый режим) - учёт платежей, зарплат, кадров
- **1С:Торговля и склад** (файловый режим) - учёт ТМЦ
- **Excel файлы** - журналы приёма, учёт пациентов, медицинские карты
- **Сканы документов** - хранятся на общем диске
- **Active Directory, DNS, DHCP, LDAP** - инфраструктура
- **Exchange Mail Server** - почта
- **ККМ** - интегрированы через TCP/IP и OLE

### Характеристики текущей системы

**Преимущества:**
- Простота управления (один сервер)
- Низкие требования к сетевой инфраструктуре
- Знакомые технологии для персонала

**Недостатки:**
- Невозможность масштабирования
- Единая точка отказа
- Сложность внесения изменений
- Отсутствие разделения ответственности
- Низкая производительность при росте нагрузки
- Отсутствие резервирования

### Объёмы данных

- **20 административных сотрудников**
- **15 медицинских специалистов**
- **Данные пациентов** - в Excel и сканах
- **Планируемый рост** - 5-кратное увеличение объёма данных
- **Планируемое расширение** - открытие новых филиалов

## Целевое состояние системы (To-Be)

### Архитектура

Планируется переход на микросервисную архитектуру с следующими компонентами:

**Новые сервисы:**
- Портал для клиентов (веб + мобильное приложение)
- Портал для сотрудников ресепшена
- Платежный шлюз
- CRM для сбора данных о клиентах
- Интеграция с лабораторией анализов через API
- BI/ML/AI сервисы для аналитики

**Технологический стек:**
- **Java/Spring Boot** - основной стек разработки
- **PostgreSQL** - основная база данных
- **ClickHouse** - аналитическая база данных
- **Kubernetes** - оркестрация контейнеров
- **Victoria Metrics** - метрики и мониторинг
- **Elasticsearch** - логирование
- **Keycloak** - управление доступом
- **HashiCorp Vault** - управление секретами
- **Apache Atlas** - управление метаданными

**Архитектурные слои:**
- Privacy Management Layer - управление конфиденциальностью
- Data Protection Layer - защита данных
- Access Control & Audit Layer - контроль доступа и аудит
- Data Lifecycle Management Layer - управление жизненным циклом
- Transparency & User Control Layer - прозрачность и контроль пользователя
- Data Loss Prevention Layer - защита от утечек
- Privacy Validation & Testing Layer - валидация конфиденциальности

### Цели миграции

1. **Масштабируемость** - поддержка 5-кратного роста объёма данных
2. **Расширение бизнеса** - открытие новых филиалов
3. **Автоматизация** - уход от ручной обработки данных
4. **Безопасность** - соответствие требованиям 152-ФЗ
5. **Удобство** - мобильное приложение для клиентов
6. **Аналитика** - BI/ML/AI сервисы для извлечения знаний из данных

## Ключевые процессы, затрагиваемые миграцией

### 1. Процессы работы с данными пациентов

**Текущее состояние:**
- Данные в Excel файлах на общем диске
- Медицинские карты в виде сканов
- Ручная обработка данных
- Отсутствие контроля доступа

**Целевое состояние:**
- Централизованная база данных с шифрованием
- Автоматическое тегирование данных
- Контроль доступа (RBAC/ABAC)
- Аудит всех операций

**Риски миграции:**
- Потеря данных при переносе
- Несоответствие форматов данных
- Необходимость валидации данных
- Длительность процесса миграции

### 2. Процессы бухгалтерского учёта

**Текущее состояние:**
- 1С:Бухгалтерия в файловом режиме
- Интеграция с ККМ через OLE
- Двойной учёт в Excel и 1С

**Целевое состояние:**
- Интеграция с новым платежным шлюзом
- Автоматическая синхронизация данных
- Единая система учёта

**Риски миграции:**
- Необходимость сохранения исторических данных
- Соответствие требованиям налоговых органов
- Непрерывность работы во время миграции
- Обучение персонала новым процессам

### 3. Процессы учёта ТМЦ

**Текущее состояние:**
- 1С:Торговля и склад в файловом режиме
- Интеграция с 1С:Бухгалтерия

**Целевое состояние:**
- Новый сервис учёта ТМЦ
- Интеграция с другими сервисами через API

**Риски миграции:**
- Синхронизация данных между системами
- Необходимость параллельной работы старых и новых систем
- Обучение сотрудников склада

### 4. Процессы записи пациентов

**Текущее состояние:**
- Ручная запись в журналах Excel
- Уведомления вручную

**Целевое состояние:**
- Автоматическая запись через портал
- Мобильное приложение для клиентов
- Автоматические уведомления
- Интеграция с календарями врачей

**Риски миграции:**
- Необходимость обучения клиентов
- Нагрузка на систему при пиковых запросах
- Интеграция с существующими процессами

### 5. Процессы обработки анализов

**Текущее состояние:**
- Ручная обработка результатов
- Хранение в файлах

**Целевое состояние:**
- Интеграция с лабораторией через API
- Автоматическая обработка результатов
- Доступ пациентов через мобильное приложение

**Риски миграции:**
- Необходимость интеграции с внешней системой
- Обеспечение безопасности при передаче данных
- Валидация данных от лаборатории

## Ключевые компоненты, затрагиваемые миграцией

### 1. Базы данных

**Текущее состояние:**
- Файловые базы 1С
- Excel файлы
- Сканы документов на диске

**Целевое состояние:**
- PostgreSQL для операционных данных
- ClickHouse для аналитики
- Объектное хранилище для документов
- Миграция всех данных в новую структуру

**Узкие места:**
- Объём данных для миграции
- Необходимость преобразования форматов
- Обеспечение целостности данных

- API Gateway для всех интеграций

**Узкие места:**
- Пропускная способность сети
- Задержки при межсервисной коммуникации
- Необходимость обеспечения отказоустойчивости
- Сложность отладки распределённой системы

### 3. Серверное оборудование

**Текущее состояние:**
- Один физический сервер в здании офиса
- Windows Server 2022

**Целевое состояние:**
- Kubernetes кластер
- Возможно облачная инфраструктура
- Горизонтальное масштабирование
- Высокая доступность

**Узкие места:**
- Необходимость нового оборудования или облака
- Стоимость инфраструктуры
- Обучение персонала работе с Kubernetes
- Обеспечение отказоустойчивости

### 4. Бизнес-логика

**Текущее состояние:**
- Логика в 1С и Excel

**Целевое состояние:**
- Микросервисы с бизнес-логикой

**Узкие места:**
- Разделение монолитной логики на сервисы
- Обеспечение консистентности данных между сервисами
- Управление транзакциями в распределённой системе

### 5. Интеграции

**Текущее состояние:**
- Интеграция 1С с ККМ через OLE

**Целевое состояние:**
- API интеграция с лабораторией
- Интеграция с платежными системами

- Интеграция с BI/ML/AI системами

**Узкие места:**
- Зависимость от внешних систем
- Необходимость обеспечения безопасности API
- Управление версиями API
- Обработка ошибок и таймаутов

## Выводы

Миграция с монолитной системы на микросервисную архитектуру затрагивает все аспекты работы компании:

1. **Данные** - необходимо мигрировать все данные из файловых систем в базы данных
2. **Инфраструктура** - переход с одного сервера на распределённую систему
3. **Процессы** - автоматизация ручных процессов
4. **Персонал** - обучение работе с новыми системами
5. **Интеграции** - переход с OLE на API
6. **Безопасность** - внедрение новых механизмов защиты

Все эти изменения создают множество потенциальных узких мест, которые могут негативно повлиять на работоспособность системы во время и после миграции. Необходимо тщательно проанализировать каждое узкое место и разработать меры по их устранению.
