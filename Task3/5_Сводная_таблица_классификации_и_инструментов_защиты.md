## Легенда к таблице

### Состояние данных:
- **At Rest** - данные при хранении (на дисках, в БД)
- **In Transit** - данные при передаче (по сети)
- **In Use** - данные при обработке (в памяти)

### Уровни чувствительности:
- **TOP_SECRET** - критически конфиденциальные (медицинские данные)
- **RESTRICTED** - высококонфиденциальные (PII, финансовые данные)
- **CONFIDENTIAL** - конфиденциальные (контакты, записи)
- **INTERNAL** - внутренние (статистика)

### Профиль риска:
- **Высокий** - высокая вероятность утечки и критический ущерб
- **Средний** - умеренная вероятность и значительный ущерб
- **Низкий** - низкая вероятность и минимальный ущерб

### Категории инструментов защиты:

**Шифрование:**
- **TDE** - Transparent Data Encryption (прозрачное шифрование БД)
- **AES-256** - алгоритм шифрования
- **TLS 1.3** - протокол шифрования при передаче
- **mTLS** - mutual TLS (взаимная аутентификация)
- **BitLocker** - шифрование дисков
- **EFS** - Encrypting File System (шифрование файлов)
- **HashiCorp Vault** - управление ключами

**Контроль доступа:**
- **RBAC** - Role-Based Access Control (контроль доступа на основе ролей)
- **ABAC** - Attribute-Based Access Control (контроль на основе атрибутов)

**Мониторинг и контроль:**
- **DLP** - Data Loss Prevention (предотвращение утечек)
- **Аудит** - логирование всех операций (pgAudit для PostgreSQL)
- **Мониторинг** - отслеживание использования данных

**Обезличивание:**
- **Токенизация** - замена идентификаторов на токены
- **Маскирование** - скрытие части данных
- **Обезличивание** - удаление или обобщение идентификаторов

## Приоритизация внедрения инструментов

### Критический приоритет (Фаза 1 - 1-2 месяца)
1. TDE для PostgreSQL - шифрование всех баз данных
2. HashiCorp Vault - управление ключами (критически важно)
3. BitLocker - шифрование дисков файлового сервера
4. TLS 1.3 - для всех веб-приложений
5. pgAudit - аудит доступа к базам данных
6. ELK Stack - централизованное логирование

### Высокий приоритет (Фаза 2 - 3-4 месяца)
7. VPN (WireGuard) - для удалённого доступа
8. API Gateway (Kong) - защита API интеграций
9. DLP-система - предотвращение утечек данных
10. Многофакторная аутентификация (Duo Security)
11. Мониторинг доступа к файлам
12. Шифрование резервных копий

### Средний приоритет (Фаза 3 - 5-6 месяцев)
13. EFS - шифрование отдельных файлов
14. mTLS - для межсервисной коммуникации
15. ML для обнаружения аномалий
16. Автоматическая проверка соответствия требованиям
17. Управление метаданными (Apache Atlas)
18. Автоматическое управление жизненным циклом данных

## Соответствие требованиям законодательства

### 152-ФЗ "О персональных данных"
- ✅ Шифрование всех персональных данных при хранении
- ✅ Шифрование при передаче (TLS)
- ✅ Контроль доступа к персональным данным
- ✅ Аудит операций с персональными данными
- ✅ Механизмы удаления данных по запросу

### Врачебная тайна (ст. 13 ФЗ-323)
- ✅ Максимальная защита медицинских данных
- ✅ Доступ только для медицинских специалистов
- ✅ Детальный аудит доступа к медицинским данным
- ✅ Предотвращение утечек через DLP

### PCI DSS (для финансовых данных)
- ✅ Шифрование данных банковских карт
- ✅ Строгий контроль доступа
- ✅ Детальный аудит операций
- ✅ Соответствие стандарту PCI DSS

## Выводы

Данная таблица представляет полную картину классификации данных компании "Медикаменте" и необходимых инструментов защиты для каждого класса данных. 

Все данные требуют защиты, но уровень защиты должен соответствовать:
- Уровню чувствительности данных
- Профилю риска
- Юридическим требованиям
- Состоянию данных (at rest, in transit, in use)

Внедрение инструментов защиты должно проводиться поэтапно, начиная с критически важных средств (Фаза 1), которые обеспечивают базовую защиту данных при минимальных затратах.
