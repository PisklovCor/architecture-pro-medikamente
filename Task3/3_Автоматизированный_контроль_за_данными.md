# Автоматизированный контроль за данными

## Введение

В данном документе описаны средства автоматизированного контроля за данными, которые необходимо внедрить в систему компании "Медикаменте". Эти средства позволяют автоматически отслеживать использование данных, обнаруживать аномалии, предотвращать утечки и обеспечивать соответствие политикам безопасности без постоянного вмешательства человека.

## Цели автоматизированного контроля

Автоматизированный контроль должен обеспечивать:

1. **Обнаружение аномалий** - автоматическое выявление подозрительной активности
2. **Предотвращение утечек** - блокировка попыток несанкционированного доступа или передачи данных
3. **Мониторинг использования данных** - отслеживание, кто, когда и какие данные использует
4. **Соответствие политикам** - автоматическая проверка соблюдения правил безопасности
5. **Быстрое реагирование** - автоматические действия при обнаружении угроз
6. **Аудит и отчётность** - автоматическое ведение логов и генерация отчётов

## 1. Data Loss Prevention (DLP) - Предотвращение утечек данных

### 1.1. DLP-система для мониторинга и блокировки утечек

**Назначение:**
Автоматическое обнаружение и предотвращение попыток передачи конфиденциальных данных за пределы компании.

**Как работает:**
- Сканирование всех исходящих данных (почта, файлы, веб-трафик)
- Распознавание конфиденциальных данных по шаблонам (регулярные выражения, ML-модели)
- Блокировка или предупреждение при попытке передачи
- Логирование всех попыток

**Функциональность:**
- **Контентный анализ** - распознавание типов данных (ФИО, паспорт, диагнозы)
- **Контекстный анализ** - анализ контекста передачи (кому, куда, зачем)
- **Политики защиты** - настраиваемые правила (блокировать, предупреждать, логировать)
- **Инцидент-менеджмент** - автоматическое создание инцидентов при нарушениях

**Применение:**
- Блокировка отправки медицинских карт на личную почту
- Предупреждение при попытке скопировать данные на USB
- Блокировка передачи данных в облачные хранилища без авторизации
- Мониторинг передачи данных через мессенджеры

**Технические решения:**

#### Вариант 1: Microsoft Purview Data Loss Prevention
- **Преимущества:** Интеграция с Microsoft экосистемой, облачное решение
- **Применение:** Для компаний, использующих Microsoft 365
- **Функции:** Защита почты, файлов, облачных хранилищ

#### Вариант 2: Symantec DLP (Broadcom)
- **Преимущества:** Комплексное решение, поддержка всех каналов утечки
- **Применение:** Для крупных компаний с высокими требованиями
- **Функции:** Защита всех каналов (почта, веб, файлы, принтеры, USB)

#### Вариант 3: Forcepoint DLP
- **Преимущества:** Простота настройки, хорошая производительность
- **Применение:** Для средних компаний
- **Функции:** Защита всех каналов, интеграция с SIEM

#### Вариант 4: Собственное решение на базе открытых инструментов
- **Компоненты:**
  - **Suricata/Zeek** - анализ сетевого трафика
  - **ClamAV с кастомными правилами** - сканирование файлов
  - **Elastic Stack** - хранение и анализ логов
  - **Собственные ML-модели** - распознавание медицинских данных
- **Преимущества:** Полный контроль, соответствие требованиям
- **Недостатки:** Требует разработки и поддержки

**Внедрение:**
1. Выбор DLP-решения (рекомендуется начать с коммерческого для быстрого внедрения)
2. Настройка политик защиты для разных типов данных
3. Обучение системы распознаванию медицинских данных
4. Настройка правил блокировки и предупреждений
5. Интеграция с системой мониторинга и алертинга
6. Тестирование на тестовых данных
7. Постепенное включение в продуктивную среду
8. Обучение сотрудников правилам работы

### 1.2. Автоматическое обнаружение конфиденциальных данных

**Назначение:**
Автоматическое сканирование систем на наличие неразмеченных конфиденциальных данных.

**Как работает:**
- Периодическое сканирование файловых систем, баз данных, облачных хранилищ
- Распознавание конфиденциальных данных по шаблонам
- Автоматическое тегирование найденных данных

- Обнаружение незашифрованных конфиденциальных файлов

- **Apache Atlas** - для Data Lake с автоматическим обнаружением
- **Собственные скрипты** - на Python с использованием регулярных выражений и ML

**Внедрение:**
1. Настройка автоматического сканирования
2. Определение шаблонов для распознавания данных

4. Настройка уведомлений
5. Планирование регулярных сканирований

## 2. Мониторинг доступа к данным (Data Access Monitoring)

### 2.1. Аудит доступа к базам данных

**Назначение:**
Автоматическое логирование всех операций с данными в базах данных для отслеживания доступа и обнаружения аномалий.

**Как работает:**
- Логирование всех SQL-запросов к базам данных
- Запись информации: кто, когда, какие данные, какая операция
- Анализ логов на предмет аномалий
- Алерты при подозрительной активности

**Применение:**
- Отслеживание доступа к медицинским картам
- Обнаружение массовых выборок данных
- Выявление доступа в нерабочее время
- Мониторинг доступа с необычных IP-адресов

**Технические решения:**

#### PostgreSQL Audit Extension (pgAudit)
- **Функции:** Детальное логирование всех операций с БД
- **Интеграция:** С ELK Stack для анализа
- **Настройка:** Гибкая настройка уровней логирования

#### Microsoft SQL Server Audit
- **Функции:** Аудит для SQL Server (если используется)
- **Интеграция:** С Windows Event Log

#### Собственное решение на уровне приложения
- **Логирование через ORM** - Hibernate/JPA interceptors
- **AOP (Aspect-Oriented Programming)** - автоматическое логирование методов доступа к данным
- **Хранение логов** - в отдельной таблице или ELK Stack

**Внедрение:**
1. Включение аудита в PostgreSQL (pgAudit)
2. Настройка уровней логирования для разных таблиц
3. Настройка отправки логов в ELK Stack
4. Создание дашбордов в Kibana для мониторинга
5. Настройка правил обнаружения аномалий
6. Настройка алертов

### 2.2. Мониторинг доступа к файлам

**Назначение:**
Отслеживание доступа к файлам с конфиденциальными данными на файловых серверах.

**Как работает:**
- Логирование всех операций с файлами (чтение, запись, копирование, удаление)
- Отслеживание доступа к папкам с медицинскими картами
- Обнаружение массового копирования файлов
- Алерты при подозрительной активности

**Применение:**
- Мониторинг доступа к папкам с медицинскими картами
- Обнаружение массового копирования данных
- Отслеживание доступа в нерабочее время
- Выявление доступа неавторизованных пользователей

**Технические решения:**

#### Windows File Server Resource Manager (FSRM)
- **Функции:** Мониторинг доступа к файлам на Windows Server
- **Интеграция:** С Windows Event Log
- **Настройка:** Групповые политики

#### Auditd для Linux (если используются Linux серверы)
- **Функции:** Системный аудит Linux
- **Интеграция:** С ELK Stack

#### Собственное решение через мониторинг файловой системы
- **Inotify (Linux)** или **File System Watcher (Windows)** - отслеживание изменений файлов
- **Отправка событий** - в ELK Stack или SIEM систему

**Внедрение:**
1. Настройка аудита доступа к файлам на файловом сервере
2. Настройка логирования для критичных папок
3. Интеграция логов с системой мониторинга
4. Настройка правил обнаружения аномалий
5. Настройка алертов

### 2.3. Мониторинг доступа к API

**Назначение:**
Отслеживание всех запросов к API для обнаружения подозрительной активности.

**Как работает:**
- Логирование всех API-запросов (кто, когда, какой endpoint, какие данные)
- Анализ паттернов запросов
- Обнаружение аномалий (массовые запросы, необычные паттерны)

- Выявление неавторизованных запросов

- **Application-level логирование** - логирование в приложениях (Spring Boot Actuator, Micrometer)
- **ELK Stack** - централизованное хранение и анализ логов
- **Grafana** - визуализация метрик доступа

**Внедрение:**
1. Настройка логирования в API Gateway
2. Настройка логирования в приложениях
3. Настройка отправки логов в ELK Stack
4. Создание дашбордов для мониторинга API
5. Настройка правил обнаружения аномалий
6. Настройка алертов

## 3. Обнаружение аномалий (Anomaly Detection)

### 3.1. Машинное обучение для обнаружения аномалий

**Назначение:**
Автоматическое обнаружение необычных паттернов в использовании данных, которые могут указывать на утечку или несанкционированный доступ.

**Как работает:**
- Обучение ML-моделей на исторических данных о нормальном использовании
- Постоянный анализ текущей активности
- Выявление отклонений от нормальных паттернов
- Алерты при обнаружении аномалий

**Типы аномалий:**
- **Временные аномалии** - доступ в нерабочее время, необычное время активности
- **Объёмные аномалии** - массовые выборки данных, необычно большие объёмы
- **Паттерн-аномалии** - необычные последовательности действий
- **Поведенческие аномалии** - действия, нехарактерные для пользователя
- **Географические аномалии** - доступ с необычных IP-адресов или локаций

**Применение:**
- Обнаружение попыток массового извлечения данных
- Выявление доступа в нерабочее время
- Обнаружение необычных паттернов запросов
- Выявление компрометированных учётных записей

**Технические решения:**

#### Elastic Machine Learning
- **Функции:** Встроенное ML в Elastic Stack для обнаружения аномалий
- **Преимущества:** Интеграция с ELK, простота использования
- **Применение:** Обнаружение аномалий в логах

#### Splunk Machine Learning Toolkit
- **Функции:** ML-инструменты для Splunk
- **Применение:** Если используется Splunk как SIEM

#### Собственные ML-модели
- **Библиотеки:** Python (scikit-learn, TensorFlow, PyTorch)
- **Алгоритмы:** Isolation Forest, One-Class SVM, Autoencoders
- **Интеграция:** С системой мониторинга через API
- **Преимущества:** Полный контроль, адаптация под специфику компании

**Внедрение:**
1. Сбор исторических данных о нормальном использовании
2. Обучение ML-моделей на нормальных паттернах
3. Интеграция моделей с системой мониторинга
4. Настройка автоматического анализа в реальном времени
5. Настройка алертов при обнаружении аномалий
6. Постоянная дообучение моделей на новых данных

### 3.2. Правила на основе политик (Policy-based Rules)

**Назначение:**
Автоматическая проверка соблюдения политик безопасности через предопределённые правила.

**Как работает:**
- Определение правил на основе политик безопасности
- Автоматическая проверка всех операций с данными
- Блокировка или предупреждение при нарушении правил
- Логирование всех нарушений

**Примеры правил:**
- **Правило минимальных привилегий** - пользователь запрашивает данные, к которым у него нет доступа
- **Правило рабочего времени** - доступ к конфиденциальным данным вне рабочего времени требует дополнительного подтверждения
- **Правило объёма данных** - массовая выборка данных требует одобрения администратора
- **Правило внешних получателей** - попытка отправить данные на внешний email блокируется
- **Правило необычных паттернов** - пользователь обращается к данным, к которым обычно не обращается

**Технические решения:**
- **OPA (Open Policy Agent)** - универсальный движок политик
- **Apache Ranger** - управление политиками для больших данных
- **Собственные правила** - в приложениях или API Gateway

**Внедрение:**
1. Документирование политик безопасности
2. Перевод политик в формализованные правила
3. Настройка проверки правил в системе
4. Настройка действий при нарушении (блокировка, предупреждение, логирование)
5. Тестирование правил
6. Мониторинг нарушений

## 4. Автоматическое управление жизненным циклом данных

### 4.1. Автоматическое удаление данных по истечении срока

**Назначение:**
Автоматическое удаление данных после истечения срока хранения согласно политикам и законодательству.

**Как работает:**
- Хранение метаданных о сроке хранения для каждого типа данных
- Периодическая проверка сроков хранения
- Автоматическое удаление или архивирование данных
- Логирование всех операций удаления

**Применение:**
- Удаление временных данных после использования
- Удаление данных по запросу пациента (право на удаление по 152-ФЗ)
- Автоматическое архивирование старых данных
- Удаление данных после истечения срока согласно политикам

**Технические решения:**
- **Собственные скрипты** - на Python или Java для периодического запуска
- **Планировщик задач** - Cron (Linux) или Task Scheduler (Windows)
- **Интеграция с БД** - триггеры или scheduled jobs в PostgreSQL
- **Workflow-системы** - Apache Airflow для управления процессами

**Внедрение:**
1. Определение сроков хранения для каждого типа данных
2. Разработка скриптов для автоматического удаления
3. Настройка планировщика задач
4. Тестирование на тестовых данных
5. Настройка логирования и уведомлений
6. Запуск в продуктивной среде

### 4.2. Автоматическое архивирование данных

**Назначение:**
Автоматическое перемещение старых данных в архивное хранилище с шифрованием.

**Как работает:**
- Определение критериев для архивирования (возраст данных, частота использования)
- Автоматическое перемещение данных в архив
- Шифрование архивных данных
- Обновление метаданных о местоположении данных

**Применение:**
- Архивирование старых медицинских карт
- Архивирование исторических данных о платежах
- Архивирование старых записей на приём

**Внедрение:**
1. Определение критериев архивирования
2. Настройка архивного хранилища с шифрованием
3. Разработка скриптов архивирования
4. Настройка автоматического запуска
5. Тестирование процесса архивирования и восстановления

## 5. Автоматическая проверка соответствия (Compliance Checking)

### 5.1. Автоматическая проверка соответствия 152-ФЗ

**Назначение:**
Автоматическая проверка соблюдения требований 152-ФЗ "О персональных данных".

**Как работает:**
- Периодическая проверка систем на соответствие требованиям
- Проверка наличия необходимых мер защиты
- Проверка корректности обработки персональных данных
- Генерация отчётов о соответствии

**Проверяемые аспекты:**
- Наличие шифрования персональных данных
- Наличие контроля доступа
- Наличие аудита операций
- Корректность обработки согласий
- Наличие механизмов удаления данных по запросу
- Корректность уведомления Роскомнадзора

**Технические решения:**
- **Собственные скрипты** - автоматическая проверка конфигураций
- **Инфраструктура как код** - проверка через Terraform/Ansible
- **Compliance-фреймворки** - использование готовых фреймворков

**Внедрение:**
1. Документирование требований 152-ФЗ
2. Разработка скриптов проверки
3. Настройка периодического запуска
4. Настройка генерации отчётов
5. Интеграция с системой мониторинга

### 5.2. Автоматическая проверка соответствия врачебной тайне

**Назначение:**
Автоматическая проверка соблюдения требований врачебной тайны.

**Проверяемые аспекты:**
- Доступ к медицинским данным только для авторизованных медицинских специалистов
- Отсутствие медицинских данных в логах
- Корректное обезличивание данных для аналитики
- Отсутствие передачи медицинских данных третьим лицам без согласия

**Внедрение:**
1. Определение правил проверки
2. Разработка автоматических проверок
3. Настройка периодического запуска
4. Настройка алертов при нарушениях

## 6. Интеграция систем контроля

### 6.1. Централизованная система мониторинга и алертинга

**Назначение:**
Объединение всех систем контроля в единую платформу для централизованного мониторинга и управления инцидентами.

**Компоненты:**
- **ELK Stack (Elasticsearch, Logstash, Kibana)** - централизованное логирование и анализ
- **Prometheus + Grafana** - мониторинг метрик и визуализация
- **SIEM система** - для комплексного анализа безопасности (опционально: Splunk, QRadar)
- **Система алертинга** - Alertmanager, PagerDuty, или собственное решение

**Функциональность:**
- Сбор логов из всех систем
- Анализ логов на предмет угроз
- Визуализация данных в дашбордах
- Автоматические алерты при обнаружении проблем
- Управление инцидентами

**Внедрение:**
1. Установка и настройка ELK Stack
