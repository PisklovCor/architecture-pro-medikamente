# Базовые инструменты защиты данных

## Введение

В данном документе описаны базовые инструменты защиты данных, которые необходимо внедрить в систему компании "Медикаменте" для обеспечения защиты данных при хранении (at rest) и при передаче (in transit). Эти инструменты являются фундаментом системы безопасности и должны быть внедрены в первую очередь.

## Шифрование данных при хранении (Encryption at Rest)

Шифрование данных при хранении защищает информацию на физических носителях: жёстких дисках, SSD, в базах данных, файловых системах, резервных копиях.

### 1. Шифрование на уровне базы данных

#### 1.1. Transparent Data Encryption (TDE) для PostgreSQL

**Назначение:**
Прозрачное шифрование данных в базе данных PostgreSQL без изменения приложений. Все данные автоматически шифруются при записи и расшифровываются при чтении.

**Как работает:**
- Шифрование происходит на уровне страниц базы данных
- Используется мастер-ключ для шифрования ключей данных
- Приложения работают без изменений
- Автоматическое шифрование всех таблиц

**Применение:**
- Шифрование всех таблиц с персональными данными пациентов
- Шифрование медицинских карт в БД
- Шифрование финансовых данных
- Шифрование данных о записях на приём

**Технические детали:**
- Алгоритм: AES-256
- Ключи хранятся в отдельном хранилище ключей (HashiCorp Vault)
- Ротация ключей каждые 90 дней
- Резервное копирование ключей в зашифрованном виде

**Внедрение:**
1. Установка расширения pgcrypto в PostgreSQL
2. Настройка TDE через конфигурацию PostgreSQL
3. Интеграция с HashiCorp Vault для управления ключами
4. Миграция существующих данных с шифрованием
5. Настройка автоматической ротации ключей

#### 1.2. Шифрование полей в базе данных (Column-level Encryption)

**Назначение:**
Шифрование отдельных критичных полей в таблицах базы данных. Используется для полей с особо чувствительными данными.

**Как работает:**
- Шифрование происходит на уровне приложения перед записью в БД
- Расшифровка происходит при чтении данных
- Разные ключи для разных типов данных
- Возможность поиска по зашифрованным данным через индексы хешей

**Применение:**
- Шифрование паспортных данных
- Шифрование номеров банковских карт
- Шифрование диагнозов и результатов анализов
- Шифрование адресов прописки

**Технические детали:**
- Алгоритм: AES-256-GCM (с аутентификацией)
- Библиотека: Java Cryptography Extension (JCE)
- Ключи: отдельные ключи для каждого типа данных
- Управление ключами через HashiCorp Vault

**Внедрение:**
1. Разработка сервиса шифрования/расшифровки данных
2. Интеграция с приложением на уровне DAO/Repository
3. Миграция существующих данных
4. Настройка управления ключами

### 2. Шифрование файловых систем

#### 2.1. BitLocker для Windows Server

**Назначение:**
Шифрование всего диска на серверах Windows Server 2022, где хранятся файлы с медицинскими картами и другими конфиденциальными данными.

**Как работает:**
- Шифрование всего тома диска
- Прозрачное для пользователей и приложений
- Защита ключа через TPM (Trusted Platform Module) или пароль
- Автоматическая разблокировка при загрузке системы

**Применение:**
- Шифрование диска файлового сервера с медицинскими картами
- Шифрование дисков серверов баз данных
- Шифрование резервных копий на дисках

**Технические детали:**
- Алгоритм: AES-128 или AES-256 (рекомендуется AES-256)
- Режим: XTS-AES
- TPM 2.0 для защиты ключей
- Восстановительные ключи хранятся в безопасном месте

**Внедрение:**
1. Проверка наличия TPM на серверах
2. Включение BitLocker через групповые политики Active Directory
3. Настройка хранения ключей восстановления
4. Шифрование существующих дисков (может занять время)
5. Мониторинг состояния шифрования

#### 2.2. Encrypting File System (EFS) для отдельных файлов

**Назначение:**
Шифрование отдельных файлов и папок на файловом сервере. Используется для дополнительной защиты критичных файлов.

**Как работает:**
- Шифрование на уровне файловой системы NTFS
- Каждый файл шифруется отдельным ключом
- Ключи файлов защищены сертификатами пользователей
- Прозрачное для приложений

**Применение:**
- Шифрование папок с медицинскими картами
- Шифрование Excel-файлов с журналами приёма
- Шифрование сканов документов

**Технические детали:**
- Алгоритм: AES-256 (по умолчанию в Windows Server 2022)
- Сертификаты пользователей для доступа
- Централизованное управление через Active Directory
- Резервное копирование сертификатов

**Внедрение:**
1. Настройка сертификатов для пользователей через Active Directory
2. Настройка групповых политик для автоматического шифрования папок
3. Шифрование существующих файлов
4. Обучение пользователей работе с зашифрованными файлами

### 3. Шифрование резервных копий

#### 3.1. Шифрование бэкапов баз данных

**Назначение:**
Защита резервных копий баз данных от несанкционированного доступа. Резервные копии часто хранятся на внешних носителях или в облаке, где риск утечки выше.

**Как работает:**
- Шифрование бэкапов перед сохранением
- Использование отдельного ключа для бэкапов
- Хранение ключей отдельно от бэкапов
- Проверка целостности при восстановлении

**Применение:**
- Резервные копии PostgreSQL
- Резервные копии ClickHouse
- Резервные копии файловых систем

**Технические детали:**
- Алгоритм: AES-256
- Инструменты: pg_dump с опцией шифрования, VeraCrypt для файлов
- Ключи: хранятся в HashiCorp Vault
- Ротация ключей каждые 90 дней

**Внедрение:**
1. Настройка автоматического шифрования бэкапов
2. Интеграция с системой управления ключами
3. Тестирование восстановления из зашифрованных бэкапов
4. Документирование процедур восстановления

#### 3.2. Шифрование бэкапов 1С

**Назначение:**
Защита резервных копий баз данных 1С:Бухгалтерия и 1С:Торговля и склад.

**Как работает:**
- Использование встроенных средств 1С для шифрования бэкапов
- Или внешнее шифрование через VeraCrypt
- Хранение ключей отдельно

**Технические детали:**
- Алгоритм: AES-256
- Инструменты: встроенные средства 1С или VeraCrypt
- Автоматизация через скрипты

**Внедрение:**
1. Настройка автоматического шифрования бэкапов 1С
2. Тестирование восстановления
3. Документирование процедур

### 4. Управление ключами шифрования

#### 4.1. HashiCorp Vault

**Назначение:**
Централизованное управление ключами шифрования, секретами, сертификатами. Критически важный компонент системы безопасности.

**Как работает:**
- Хранение ключей в зашифрованном хранилище
- API для получения ключей приложениями
- Ротация ключей
- Аудит всех операций с ключами
- Разделение доступа к ключам

**Функциональность:**
- Генерация криптографических ключей
- Хранение секретов (пароли, API-ключи)
- Управление сертификатами
- Ротация ключей
- Аудит доступа к ключам

**Применение:**
- Хранение ключей шифрования баз данных
- Хранение ключей шифрования файлов
- Хранение паролей к внешним системам
- Хранение API-ключей для интеграций

**Технические детали:**
- Алгоритм шифрования хранилища: AES-256-GCM
- Доступ через REST API с аутентификацией
- Интеграция с Active Directory для аутентификации
- Резервное копирование хранилища
- High Availability конфигурация

**Внедрение:**
1. Установка HashiCorp Vault на отдельном сервере
2. Настройка высокой доступности (HA)
3. Интеграция с Active Directory
4. Настройка политик доступа к ключам
5. Миграция существующих ключей и секретов
6. Интеграция с приложениями для автоматического получения ключей

## Шифрование данных при передаче (Encryption in Transit)

Шифрование данных при передаче защищает информацию во время её передачи по сети между системами, компонентами, пользователями.

### 1. TLS/SSL для веб-приложений

#### 1.1. TLS 1.3 для всех HTTP/HTTPS соединений

**Назначение:**
Защита всех соединений между клиентами (браузеры, мобильные приложения) и серверами компании.

**Как работает:**
- Шифрование всего трафика между клиентом и сервером
- Аутентификация сервера через сертификаты
- Защита от перехвата и подмены данных
- Perfect Forward Secrecy (PFS) - защита прошлых сессий

**Применение:**
- Портал для клиентов (HTTPS)
- Портал для сотрудников (HTTPS)
- Мобильное приложение (HTTPS API)
- Административные панели (HTTPS)

**Технические детали:**
- Протокол: TLS 1.3 (минимальная версия TLS 1.2)
- Алгоритмы: AES-256-GCM, ChaCha20-Poly1305
- Сертификаты: Let's Encrypt или внутренний CA
- HSTS (HTTP Strict Transport Security) для принудительного HTTPS
- Отключение устаревших протоколов (SSL 3.0, TLS 1.0, TLS 1.1)

**Внедрение:**
1. Получение SSL/TLS сертификатов (Let's Encrypt или внутренний CA)
2. Настройка веб-серверов (Nginx, Apache) для TLS 1.3
3. Настройка HSTS заголовков
4. Отключение устаревших протоколов
5. Тестирование через SSL Labs
6. Настройка автоматического обновления сертификатов

#### 1.2. Mutual TLS (mTLS) для межсервисной коммуникации

**Назначение:**
Взаимная аутентификация сервисов при межсервисном взаимодействии. Обе стороны должны иметь сертификаты.

**Как работает:**
- Каждый сервис имеет свой сертификат
- При установлении соединения обе стороны проверяют сертификаты друг друга
- Защита от подмены сервисов
- Шифрование всего трафика

**Применение:**
- Коммуникация между микросервисами
- Интеграция с лабораторией анализов через API
- Коммуникация между компонентами системы
- Доступ к внутренним API

**Технические детали:**
- Протокол: TLS 1.3 с взаимной аутентификацией
- Сертификаты: внутренний Certificate Authority (CA)
- Управление сертификатами: автоматическая выдача и ротация
- Инструменты: HashiCorp Vault PKI, cert-manager для Kubernetes

**Внедрение:**
1. Настройка внутреннего CA (через HashiCorp Vault PKI)
2. Выдача сертификатов для всех сервисов
3. Настройка автоматической ротации сертификатов
4. Интеграция с приложениями для использования mTLS
5. Мониторинг истечения сертификатов

### 2. VPN для удалённого доступа и межсерверного взаимодействия

#### 2.1. VPN для удалённого доступа сотрудников

**Назначение:**
Защищённый доступ сотрудников к внутренним системам компании извне офиса.

**Как работает:**
- Создание зашифрованного туннеля между устройством сотрудника и сервером компании
- Все данные передаются через зашифрованный туннель
- Аутентификация пользователей
- Контроль доступа к ресурсам

**Применение:**
- Удалённая работа сотрудников
- Доступ к файловому серверу из дома
- Доступ к базам данных для администраторов
- Доступ к системам управления

**Технические детали:**
- Протокол: OpenVPN или WireGuard (рекомендуется WireGuard - быстрее и безопаснее)
- Шифрование: ChaCha20-Poly1305 (WireGuard) или AES-256 (OpenVPN)
- Аутентификация: сертификаты + MFA (многофакторная аутентификация)
- Интеграция с Active Directory

**Внедрение:**
1. Установка VPN-сервера (WireGuard или OpenVPN)
2. Настройка интеграции с Active Directory
3. Настройка MFA для VPN-доступа
4. Выдача сертификатов/ключей сотрудникам
5. Настройка клиентов на устройствах сотрудников
6. Обучение сотрудников использованию VPN

#### 2.2. Site-to-Site VPN для связи между филиалами

**Назначение:**
Защищённая связь между офисами компании при открытии филиалов.

**Как работает:**
- Постоянное зашифрованное соединение между офисами
- Все данные между офисами передаются через VPN
- Прозрачно для пользователей

**Применение:**
- Синхронизация данных между филиалами
- Доступ к централизованным системам из филиалов
- Общий доступ к ресурсам

**Технические детали:**
- Протокол: IPsec или WireGuard
- Шифрование: AES-256 или ChaCha20-Poly1305
- Постоянное соединение (always-on)

**Внедрение:**
1. Настройка VPN-туннелей между офисами
2. Настройка маршрутизации
3. Тестирование соединения
4. Мониторинг стабильности соединения

### 3. Защита API

#### 3.1. API Gateway с шифрованием и аутентификацией

**Назначение:**
Единая точка входа для всех API-запросов с обеспечением безопасности.

**Как работает:**
- Все API-запросы проходят через API Gateway
- Проверка аутентификации и авторизации
- Шифрование трафика (TLS)
- Логирование всех запросов
- Ограничение скорости запросов (rate limiting)

**Применение:**
- Интеграция с лабораторией анализов
- API для мобильного приложения
- API для внешних партнёров
- Внутренние API между сервисами

**Технические детали:**
- Инструменты: Kong, Apache APISIX, или собственное решение на Spring Cloud Gateway
- Аутентификация: OAuth 2.0, JWT токены
- Шифрование: TLS 1.3
- Rate limiting: защита от DDoS
- Логирование: все запросы в ELK Stack

**Внедрение:**
1. Установка и настройка API Gateway
2. Настройка маршрутизации API
3. Интеграция с системой аутентификации (Keycloak)
4. Настройка TLS сертификатов
5. Настройка rate limiting
6. Настройка логирования
7. Миграция существующих API через Gateway

#### 3.2. OAuth 2.0 и JWT для аутентификации API

**Назначение:**
Безопасная аутентификация и авторизация при доступе к API.

**Как работает:**
- Клиент получает токен доступа через OAuth 2.0
- Токен передаётся в заголовке каждого API-запроса
- Сервер проверяет токен и права доступа
- Токены имеют ограниченный срок жизни

**Применение:**
- Доступ к API из мобильного приложения
- Доступ к API для интеграций
- Доступ к API для внешних партнёров

**Технические детали:**
- Протокол: OAuth 2.0 с JWT токенами
- Инструменты: Keycloak для выдачи токенов
- Алгоритм подписи JWT: RS256 (RSA)
- Срок жизни токена: 15 минут для access token, 7 дней для refresh token
- Отзыв токенов при необходимости

**Внедрение:**
1. Настройка Keycloak для OAuth 2.0
2. Регистрация клиентов (мобильное приложение, партнёры)
3. Интеграция API с проверкой JWT токенов
4. Настройка refresh token механизма
5. Тестирование аутентификации

### 4. Защита почтовых сообщений

#### 4.1. Шифрование почты (S/MIME или PGP)

**Назначение:**
Защита электронной почты с конфиденциальными данными пациентов.

**Как работает:**
- Шифрование содержимого письма
- Цифровая подпись для подтверждения отправителя
- Защита от перехвата и подмены

**Применение:**
- Пересылка медицинских данных по почте
- Отправка результатов анализов
- Передача конфиденциальной информации

**Технические детали:**
- Стандарт: S/MIME (проще в использовании) или PGP
- Сертификаты: внутренний CA или коммерческие
- Интеграция с Exchange Mail Server
- Автоматическое шифрование писем с определёнными тегами

**Внедрение:**
1. Настройка S/MIME сертификатов для сотрудников
2. Интеграция с Exchange Server
3. Настройка автоматического шифрования
4. Обучение сотрудников использованию

#### 4.2. TLS для SMTP/IMAP/POP3

**Назначение:**
Защита соединений почтового сервера с клиентами и другими серверами.

**Как работает:**
- Принудительное использование TLS для всех почтовых соединений
- Защита от перехвата почты

**Технические детали:**
- TLS 1.3 для всех почтовых протоколов
- Принудительное TLS (не разрешать незашифрованные соединения)

**Внедрение:**
1. Настройка Exchange Server для принудительного TLS
2. Настройка сертификатов
3. Тестирование соединений

### 5. Защита интеграции с внешними системами

#### 5.1. Защита интеграции с лабораторией анализов

**Назначение:**
Безопасная передача данных о результатах анализов между компанией и лабораторией.

**Как работает:**
- mTLS для взаимной аутентификации
- Шифрование всех данных
- Проверка целостности данных
- Логирование всех операций

**Технические детали:**
- Протокол: HTTPS с mTLS
- Формат данных: JSON с цифровой подписью
- Аутентификация: сертификаты с обеих сторон
- Валидация данных на стороне получателя

**Внедрение:**
1. Согласование формата API с лабораторией
2. Обмен сертификатами
3. Настройка mTLS соединения
4. Реализация валидации данных
5. Настройка логирования
6. Тестирование интеграции

#### 5.2. Защита интеграции ККМ с 1С

**Назначение:**
Защита данных о платежах при передаче от ККМ в 1С.

**Текущая проблема:**
- Интеграция через OLE и TCP/IP без шифрования
- Данные передаются в открытом виде

**Решение:**
- Замена на защищённое API соединение
- Шифрование через TLS

**Внедрение:**

## Приоритизация внедрения инструментов защиты

### Фаза 1 (Критическая - 1-2 месяца)

1. **TLS 1.3 для всех веб-приложений** - защита данных при передаче клиентам
2. **TDE для PostgreSQL** - шифрование данных в основной базе данных
3. **BitLocker для файлового сервера** - шифрование медицинских карт на диске
4. **HashiCorp Vault** - управление ключами (критически важно)

### Фаза 2 (Высокий приоритет - 3-4 месяца)

5. **Column-level encryption** - шифрование критичных полей
6. **VPN для удалённого доступа** - защита удалённых соединений
7. **API Gateway с TLS** - защита API интеграций
8. **Шифрование резервных копий** - защита бэкапов

### Фаза 3 (Средний приоритет - 5-6 месяцев)

9. **mTLS для межсервисной коммуникации** - защита внутренних соединений
10. **EFS для файлов** - дополнительная защита файлов
11. **Шифрование почты** - защита почтовых сообщений
12. **Site-to-Site VPN** - защита связи между филиалами

## Выводы

Базовые инструменты защиты данных обеспечивают:

1. **Защиту при хранении** - данные зашифрованы на дисках, в базах данных, в резервных копиях
2. **Защиту при передаче** - все соединения зашифрованы через TLS/VPN
3. **Управление ключами** - централизованное и безопасное управление ключами шифрования
4. **Соответствие требованиям** - выполнение требований 152-ФЗ, врачебной тайны, PCI DSS

Эти инструменты являются основой системы безопасности и должны быть внедрены в первую очередь, до внедрения более сложных систем контроля и мониторинга.
