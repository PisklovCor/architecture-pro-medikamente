# Метрики эффективности классификации данных

## Введение

Данный документ описывает метрики, которые будут использоваться для оценки эффективности работы движка классификации данных. Эти метрики необходимы для мониторинга качества классификации, выявления проблем и оптимизации системы.

## Цели использования метрик

Метрики эффективности классификации данных используются для:

1. **Оценки качества классификации** - насколько точно движок определяет уровень конфиденциальности данных
2. **Выявления проблем** - обнаружение ошибок классификации и их причин
3. **Оптимизации системы** - улучшение алгоритмов классификации на основе метрик
4. **Мониторинга производительности** - отслеживание скорости и ресурсопотребления
5. **Соответствия требованиям** - обеспечение соблюдения политик конфиденциальности

## Категории метрик

### 1. Метрики точности классификации

Эти метрики показывают, насколько правильно движок определяет уровень конфиденциальности данных.

#### 1.1. Accuracy (Точность)

**Определение:** Доля правильно классифицированных записей от общего количества.

**Формула:**
```
Accuracy = (Количество правильных классификаций) / (Общее количество записей)
```

**Целевое значение:** > 95%

**Использование:**
- Общая оценка качества классификации
- Сравнение версий движка
- Мониторинг деградации качества

**Пример:**
- Всего обработано: 10000 записей
- Правильно классифицировано: 9600 записей
- Accuracy = 9600 / 10000 = 96%

#### 1.2. Precision (Точность по классу)

**Определение:** Доля записей, правильно классифицированных как определённый уровень, от всех записей, классифицированных как этот уровень.

**Формула:**
```
Precision = (True Positives) / (True Positives + False Positives)
```

**Целевые значения:**
- TOP_SECRET: > 98% (критически важно не пропустить)
- RESTRICTED: > 95%
- CONFIDENTIAL: > 90%
- INTERNAL: > 85%

**Использование:**
- Оценка качества классификации для каждого уровня конфиденциальности
- Выявление проблем с переклассификацией (например, CONFIDENTIAL классифицирован как INTERNAL)

**Пример для TOP_SECRET:**
- Классифицировано как TOP_SECRET: 500 записей
- Правильно классифицировано: 490 записей
- Precision = 490 / 500 = 98%

#### 1.3. Recall (Полнота)

**Определение:** Доля записей определённого уровня, которые были правильно классифицированы, от всех записей этого уровня.

**Формула:**
```
Recall = (True Positives) / (True Positives + False Negatives)
```

**Целевые значения:**
- TOP_SECRET: > 99% (критически важно не пропустить)
- RESTRICTED: > 95%
- CONFIDENTIAL: > 90%
- INTERNAL: > 85%

**Использование:**
- Выявление пропущенных записей высокого уровня конфиденциальности
- Критично для TOP_SECRET - нельзя пропустить медицинские данные

**Пример для TOP_SECRET:**
- Всего записей TOP_SECRET: 500
- Правильно классифицировано: 495
- Recall = 495 / 500 = 99%

#### 1.4. F1-Score (Гармоническое среднее)

**Определение:** Гармоническое среднее между Precision и Recall.

**Формула:**
```
F1-Score = 2 * (Precision * Recall) / (Precision + Recall)
```

**Целевые значения:**
- TOP_SECRET: > 98%
- RESTRICTED: > 95%
- CONFIDENTIAL: > 90%
- INTERNAL: > 85%

**Использование:**
- Балансированная оценка качества классификации
- Учёт как точности, так и полноты

#### 1.5. Confusion Matrix (Матрица ошибок)

**Определение:** Таблица, показывающая распределение правильных и неправильных классификаций по всем уровням.

**Пример матрицы:**
```
                Классифицировано как:
                TOP_SECRET  RESTRICTED  CONFIDENTIAL  INTERNAL
TOP_SECRET      490         8           2             0
RESTRICTED       5          950         40            5
CONFIDENTIAL     0          30          900           70
INTERNAL         0          5           20            975
```

**Использование:**
- Визуализация типов ошибок классификации
- Выявление паттернов неправильной классификации
- Определение приоритетов для улучшения

### 2. Метрики производительности

Эти метрики показывают, насколько быстро и эффективно работает движок.

#### 2.1. Throughput (Пропускная способность)

**Определение:** Количество записей, обрабатываемых в единицу времени.

**Формула:**
```
Throughput = (Количество обработанных записей) / (Время обработки)
```

**Единицы измерения:** записей/секунду, записей/минуту

**Целевое значение:** 
- Потоковая обработка: > 1000 записей/секунду
- Пакетная обработка: > 10000 записей/минуту

**Использование:**
- Оценка способности обрабатывать растущий объём данных
- Планирование масштабирования
- Выявление узких мест производительности

#### 2.2. Latency (Задержка)

**Определение:** Время от момента поступления данных до завершения классификации.

**Формула:**
```
Latency = (Время завершения) - (Время поступления)
```

**Единицы измерения:** миллисекунды, секунды

**Целевые значения:**
- Потоковая обработка: < 100 мс (p95)
- Пакетная обработка: < 5 секунд на батч

**Использование:**
- Оценка времени отклика системы
- Выявление проблем производительности
- Обеспечение SLA для пользователей

#### 2.3. Processing Time (Время обработки)

**Определение:** Время, затрачиваемое на классификацию одной записи или батча.

**Метрики:**
- Среднее время обработки записи
- Медианное время обработки
- P95, P99 процентили времени обработки

**Использование:**
- Оптимизация алгоритмов классификации
- Выявление медленных компонентов
- Планирование ресурсов

#### 2.4. Resource Utilization (Использование ресурсов)

**Определение:** Использование CPU, памяти, диска, сети.

**Метрики:**
- CPU usage (%)
- Memory usage (GB, %)
- Disk I/O (MB/s)
- Network I/O (MB/s)

**Использование:**
- Планирование масштабирования
- Выявление узких мест
- Оптимизация использования ресурсов

### 3. Метрики надёжности

Эти метрики показывают стабильность и надёжность работы движка.

#### 3.1. Error Rate (Частота ошибок)

**Определение:** Доля записей, при обработке которых возникли ошибки.

**Формула:**
```
Error Rate = (Количество ошибок) / (Общее количество записей)
```

**Целевое значение:** < 0.1%

**Использование:**
- Оценка стабильности системы
- Выявление проблемных источников данных
- Мониторинг качества данных

#### 3.2. Availability (Доступность)

**Определение:** Доля времени, в течение которого движок доступен и работает.

**Формула:**
```
Availability = (Время работы) / (Общее время) * 100%
```

**Целевое значение:** > 99.9% (uptime)

**Использование:**
- Оценка надёжности системы
- Планирование обслуживания
- Обеспечение SLA

#### 3.3. Mean Time Between Failures (MTBF)

**Определение:** Среднее время между сбоями системы.

**Использование:**
- Оценка надёжности
- Планирование обслуживания

#### 3.4. Mean Time To Recovery (MTTR)

**Определение:** Среднее время восстановления после сбоя.

**Использование:**
- Оценка способности быстро восстанавливаться
- Планирование процедур восстановления

### 4. Метрики адаптивности

Эти метрики показывают, насколько хорошо движок адаптируется к изменениям в данных.

#### 4.1. Schema Change Detection Rate (Скорость обнаружения изменений схемы)

**Определение:** Доля изменений схемы, обнаруженных автоматически.

**Формула:**
```
Detection Rate = (Обнаруженные изменения) / (Все изменения) * 100%
```

**Целевое значение:** > 95%

**Использование:**
- Оценка способности адаптироваться к изменениям
- Выявление проблем с обнаружением новых полей

#### 4.2. Time to Adapt (Время адаптации)

**Определение:** Время от обнаружения изменения схемы до обновления правил классификации.

**Целевое значение:** < 24 часа для критических изменений

**Использование:**
- Оценка скорости реакции на изменения
- Планирование процессов обновления

#### 4.3. Classification Confidence (Уверенность в классификации)

**Определение:** Средняя уверенность движка в правильности классификации.

**Формула:**
```
Confidence = Среднее значение confidence score для всех записей
```

**Целевое значение:** > 0.9 (где 1.0 - максимальная уверенность)

**Использование:**
- Выявление записей с низкой уверенностью (требуют ручной проверки)
- Оценка качества правил классификации

### 5. Метрики соответствия требованиям

Эти метрики показывают соблюдение политик конфиденциальности и требований законодательства.

#### 5.1. Policy Compliance Rate (Соответствие политикам)

**Определение:** Доля данных, соответствующих политикам конфиденциальности.

**Формула:**
```
Compliance Rate = (Данные, соответствующие политикам) / (Все данные) * 100%
```

**Целевое значение:** 100%

**Использование:**
- Оценка соблюдения требований
- Выявление нарушений политик
- Отчёты для аудита

#### 5.2. Data Leakage Prevention (Предотвращение утечек)

**Определение:** Количество попыток загрузки данных высокого уровня конфиденциальности без обработки.

**Целевое значение:** 0 (все попытки должны блокироваться)

**Использование:**
- Оценка эффективности защиты
- Выявление попыток обхода защиты

#### 5.3. Anonymization Quality (Качество обезличивания)

**Определение:** Оценка качества обезличивания данных (для TOP_SECRET).

**Метрики:**
- k-анонимность: k >= 5
- l-разнообразие: l >= 3
- Риск реидентификации: < 0.01

**Использование:**
- Оценка качества обезличивания
- Выявление рисков реидентификации
- Оптимизация методов обезличивания

## Использование метрик для оптимизации

### Процесс оптимизации

1. **Сбор метрик** - непрерывный сбор всех метрик в реальном времени
2. **Анализ метрик** - выявление проблем и узких мест
3. **Определение приоритетов** - выбор наиболее критичных проблем для решения
4. **Внесение изменений** - улучшение алгоритмов, правил, инфраструктуры
5. **Оценка результатов** - сравнение метрик до и после изменений
6. **Итерация** - повторение процесса для дальнейшей оптимизации

### Примеры оптимизации на основе метрик

#### Пример 1: Низкая точность классификации TOP_SECRET

**Проблема:** Precision для TOP_SECRET = 85% (целевое > 98%)

**Анализ:**
- Анализ Confusion Matrix показывает, что многие TOP_SECRET классифицируются как RESTRICTED
- Причина: новые поля с медицинскими данными не распознаются

**Решение:**
- Обновление словаря ключевых слов для медицинских терминов
- Добавление правил для новых полей
- Улучшение content-based классификации для медицинских данных

**Ожидаемый результат:** Precision для TOP_SECRET > 98%

#### Пример 2: Низкая производительность

**Проблема:** Throughput = 500 записей/секунду (целевое > 1000)

**Анализ:**
- Высокое использование CPU (95%)
- Медленная обработка регулярных выражений

**Решение:**
- Оптимизация регулярных выражений
- Кэширование результатов классификации для похожих записей
- Параллельная обработка батчей

**Ожидаемый результат:** Throughput > 1000 записей/секунду

#### Пример 3: Медленная адаптация к изменениям

**Проблема:** Time to Adapt = 72 часа (целевое < 24 часа)

**Анализ:**
- Ручной процесс обновления правил
- Отсутствие автоматизации

**Решение:**
- Автоматическое обновление правил для новых полей
- ML-модель для предсказания типа новых полей
- Уведомления администраторов о критических изменениях

**Ожидаемый результат:** Time to Adapt < 24 часа

## Дашборды и отчёты

### Реaltime Dashboard (Дашборд в реальном времени)

**Метрики:**
- Текущий Throughput
- Текущая Latency (p95, p99)
- Текущий Error Rate
- Использование ресурсов (CPU, память)
- Количество обработанных записей за последний час

**Использование:**
- Мониторинг работы системы в реальном времени
- Быстрое обнаружение проблем
- Оценка текущей нагрузки

### Daily Report (Ежедневный отчёт)

**Метрики:**
- Accuracy, Precision, Recall, F1-Score по всем уровням
- Общее количество обработанных записей
- Количество ошибок
- Время обработки (среднее, медиана, p95, p99)
- Использование ресурсов

**Использование:**
- Ежедневная оценка качества работы
- Выявление трендов
- Планирование улучшений

### Weekly Report (Еженедельный отчёт)

**Метрики:**
- Все метрики из ежедневного отчёта (агрегированные)
- Confusion Matrix за неделю
- Тренды метрик за неделю
- Анализ изменений схемы данных
- Отчёты о соответствии политикам

**Использование:**
- Еженедельная оценка работы системы
- Выявление долгосрочных трендов
- Планирование долгосрочных улучшений

### Monthly Report (Ежемесячный отчёт)

**Метрики:**
- Все метрики из еженедельного отчёта (агрегированные)
- Анализ производительности за месяц
- Отчёты о масштабировании
- Отчёты о соответствии требованиям законодательства
- Рекомендации по улучшению

**Использование:**
- Ежемесячная оценка работы системы
- Отчёты для руководства
- Планирование бюджета и ресурсов
